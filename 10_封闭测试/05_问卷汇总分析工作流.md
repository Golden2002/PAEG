# PAEG 封闭测试 · 问卷汇总分析工作流（v1.0）

> **用途**（内部）：把用户反馈转化为**可执行的改进目标**，直接驱动项目针对性优化。
> **流程**：收集问卷 → 结构化汇总 → 聚类分析 → 生成改进目标（Goals）→ 排期实施 → 闭环验证
> **版本**：v1.0 · 2026-08-21 · 对接项目需求文档纪律（D1-D4）

---

## 一、工作流总览

```
用户反馈问卷
    │
    ▼
① 收集归档 ──→ 10_封闭测试/用户反馈/（每用户一份）
    │
    ▼
② 结构化汇总 ──→ 汇总表（Excel/CSV）：按维度归集所有反馈条目
    │
    ▼
③ 聚类分析 ──→ 识别高频问题 + 严重问题 + 亮点（3 类输出）
    │
    ▼
④ 生成改进目标 ──→ Goals 清单（SMART：可测/可验收/有优先级）
    │
    ▼
⑤ 排期实施 ──→ 登记需求文档（§3.x）+ 按优先级实施
    │
    ▼
⑥ 闭环验证 ──→ 验证改进效果 + 在反馈表中回访用户
```

---

## 二、步骤详解

### ① 收集归档（测试期持续）

- 用户反馈通过微信/邮件提交，按用户编号归档到 `10_封闭测试/用户反馈/`
- 命名规范：`反馈_{用户昵称}_{日期}.md`
- 每份反馈先做**数据完整性检查**：基本信息齐不齐？流程表编号对应否？

### ② 结构化汇总（每批问卷到达后）

将全部反馈汇总为一张表（推荐 `10_封闭测试/分析报告/` 下 Excel）：

| 维度 | 列 |
|---|---|
| 用户 | 昵称 / 身份（学生/老师/家长）/ 学段 |
| 功能域 | 教学讲解 / 教案 / PPT / 讲义 / 备课全流程 / 使用体验 |
| 反馈类型 | 😄满意 / 🙂还行 / 😕不满意 / ⚠️故障 / 💡建议 |
| 内容 | 原话摘要（保留用户原意） |
| 严重度 | 高（影响核心使用）/ 中 / 低 |

**工具**：Python 脚本或手工整理均可；反馈量 >20 份时用脚本半自动归集。

### ③ 聚类分析（产出 3 类结论）

| 输出 | 定义 | 示例 |
|---|---|---|
| **高频问题** | ≥3 个用户提到的同类问题 | "教案生成太慢"（5 人提及） |
| **严重问题** | 影响核心链路 / 内容错误 | "PPT 里有公式错误" |
| **亮点** | 用户明确好评的能力 | "讲课很耐心，例子生活化" |

**方法**：
1. 按"功能域 × 反馈类型"交叉统计，找出高频格子
2. 逐条读"不满意"内容，归并同类（3-5 条同类 → 1 个主题）
3. 标注每个主题的**用户原话证据**（避免失真）

### ④ 生成改进目标（Goals）——核心产出

每条聚类主题 → 转化成一个**SMART 改进目标**：

| 要素 | 要求 | 示例 |
|---|---|---|
| S 具体 | 指明功能点 | "教案生成加入'基础模板'选项" |
| M 可测 | 有量化验收 | "教案生成时间 ≤30 秒" |
| A 可实现 | 技术可行 | 参考现有架构（39 功能×55 模块矩阵） |
| R 相关 | 对齐用户反馈 | 源于 ≥3 条用户原话 |
| T 有时限 | 有目标版本 | "v1.3.0 前完成" |

**Goal 模板**（写入 `10_封闭测试/分析报告/改进目标清单.md`）：

```markdown
### GOAL-XX：{一句话目标}

- **来源**：{用户原话引用，≥1 条}
- **频次**：{N} 人提及 / 严重度
- **现状**：{当前行为，文件/端点证据}
- **期望**：{可测的验收标准}
- **优先级**：P0（立即）/ P1（近期）/ P2（排期）
- **负责人**：{开发/DeepSeek Harness}
- **状态**：待实施 / 实施中 / 已实施 / 已验证
```

### ⑤ 排期实施（对接项目纪律）

- 每个 Goal 按 D1 纪律登记到 `PAEG_任务总清单与操作规范.md`（新 §3.x）
- 优先级规则：
  - **P0**：严重问题（内容错误/核心链路故障）→ 立即修
  - **P1**：高频问题（≥3 人）→ 本周实施
  - **P2**：单点建议 / 亮点强化 → 排期
- 实施走 TDD（测试先行）+ D4 文档同步（技术说明/技术全景/元能力/维护手册）

### ⑥ 闭环验证（关键——不闭环则改进无效）

| 环节 | 做法 |
|---|---|
| 实施后验证 | 按 Goal 的"可测验收标准"回归测试 |
| 用户回访 | 对提交该反馈的用户做简短回访："你提的问题我们改了，试试看？" |
| 效果记录 | 在 Goal 状态标注验证结果 + 回访反馈 |

## 四、执行节奏建议

| 阶段 | 触发 | 动作 |
|---|---|---|
| 收集期 | 测试进行中 | 每收 5 份 → 快速扫一遍严重度 |
| 批汇总 | 每批 10-15 份 | 出汇总表 + 聚类分析 |
| 目标发布 | 每批汇总后 | 出改进目标清单（P0/P1 先定） |
| 实施期 | 目标发布后 | P0 立即、P1 本周、P2 排期 |
| 复盘 | 每轮测试结束 | 回访 + 效果验证 + 归档 |

## 五、与项目现有体系的对接

| 对接点 | 说明 |
|---|---|
| 需求文档纪律 | 每个 Goal 登记 §3.x（D1 先登记后实施） |
| 连通性矩阵 | 改进涉及的功能/模块在矩阵中标注（§10.21） |
| 总需求文档 | 严重/高频问题若属商业化缺口 → 同步到 TOP 优先级 |
| 测试回归 | 改后跑 audit_check + smoke_test + pytest |
| 文档同步 | D4：技术说明/全景/元能力/维护手册四文档更新 |
