> 评估方法：源码规模实测 + 分层结构核验 + 插件化机制核查（证据驱动）

## 二、智能体架构合理性（专家评估）

**优点（成熟度较高的 Agent 架构）**：
1. **能力分层清晰**：内置工具（22）→ 配置层 MCP（14）→ 按需 Skill（11）→ 接入 MCP server（6）→ 编排 Workflow（4）——五层能力体系，扩展零侵入
2. **LLM 先判断、规则兜底**（元能力 L918 铁律）：语义判断交给 LLM，确定性兜底交给规则——正确的能力分级
3. **质量控制模块化**：lang_gate（语言规范）+ constraint_engine（L0-L8 约束）+ quality_gate + material gates——质量门独立可插拔
4. **可观测性**：observability + rollout 持久化 + session event log + trace_id——审计可回放
5. **安全分层**：sandbox（工具分域）+ approval + rate-limit + token 认证——运行时治理

**改进点（重构建议）**：
1. subagents.py 4484 行 → 按 subagent 拆分为 agents/ 目录（diagnostor/planner/presenter/evaluator 各一文件）——README 已规划 Phase 4 但未执行
2. prompts.py 2805 行 → 按学科/学段拆分为 data/prompts/ 配置化加载（prompt_loader 已有，但主体仍集中在单文件）
3. server.py 3541 行 → 端点已蓝图化，但生成器/工具函数仍驻留 server.py，应下沉到 services/

## 三、工具生态适应性（核心评估）

| 维度 | 机制 | 评估 |
|---|---|---|
| MCP 双向 | mcp_gateway（对外 3 server）+ mcp_client（对内）| ✅ 双向打通 |
| 插件化 | config_hub（配置驱动）+ workflows_hub（声明式 DAG）+ skill_registry（渐进披露） | ✅ 成熟 |
| 独立库桥接 | infra/lang_plugin_bridge.py（语言规范插件桥）+ material_bridge（物料插件双轨） | ✅ 14.x 独立库可插拔接入 |
| 动态发现 | /api/mcp/tools + tools/list + mcp_servers.json | ✅ 主 Agent 运行时发现 |
| 工具生态目录 | 14.x 平级独立库（14.1~14.6）+ 各自 GitHub/modelscope | ✅ 结构清晰 |
| 新工具接入成本 | 新增 MCP = 改 JSON；新增 Skill = 丢 SKILL.md；新增 Workflow = 丢 JSON | ✅ 零代码侵入 |

**结论**：工具生态适应性**良好**——「一切皆插件」的 DSH 式架构已落地（config_hub/workflows_hub/skill_registry/subagent_registry/MCP 双向/独立库桥接），新工具可通过 MCP 三原语接入并被主 Agent 动态发现调度。**这是 PAEG 架构最成熟的部分**。

## 五、总体结论

- **智能体架构**：成熟（五层能力 + 质量门 + 可观测 + 安全分层），属业界中上水平
- **工具生态适应性**：**优秀**（DSH 式插件化 + MCP 三原语 + 独立库桥接 + 动态发现），是核心壁垒
- **重构需求**：三个巨型文件（server.py/subagents.py/prompts.py）是主要技术债；词汇表产物质量（OCR 断词/污染词）是功能债，需优先修复以满足"超越范本"要求
