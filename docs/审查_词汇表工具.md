### 2.1 web/ 结构与页面清单

### 2.2 前端 ↔ 后端能力映射核查

- **前端引用的每个端点后端均真实存在**，无"按钮但后端没有"的悬空调用：`/api/upload`→`web_api.py:45`、`/api/presets`→`:37`、`/api/generate`→`:58`、`/api/download`→`:77` ✅
- **反向缺口（后端有、前端不可达）**：
  - 语种选择（后端 `lang` 参数支持 en/de/fr/es，前端硬编码 `lang:"en"`，`index.html:129`）
  - 多维度筛选（后端 `user_filter` 支持 exam/score/vocab_size/domains/max_entries，前端仅传 preset）
  - 9 个 executor 工具中 5 个（lookup_word/quantile_of/extract_collocations/clean_examples/validate_entry）无前端 UI——终端用户场景下属合理分层，非缺陷
- **完整闭环判定**：上传→档位筛选→生成→下载 **可跑通**（实测 + web 测试全绿），但"**词条浏览**"环节缺失（用户任务要求：导入→筛选→词条浏览→产物→渲染导出），浏览只能下载 HTML 后打开，页面内无词条列表/搜索/分页。

### 2.3 前端缺口清单

1. 无词条浏览/搜索/分页 UI（对标单词鸭自建词库的词条管理）
2. 无词频/词性/难度自定义筛选 UI（仅预设档位）
3. 无语种选择（de/fr/es 能力前端不可达）
4. 生成过程同步阻塞（5-20 分钟无进度反馈，无任务轮询/断点续跑 UI）
5. 无词条编辑/精选/导出词库（.csv/Anki）功能

## 五、审查中发现的新缺陷（非基线标注范围，如实列出）

1. **例句清洗粘连 bug**：`clean_examples(["Good [1] sentence"])` 实测返回 `["Goodsentence"]`——`example_sanitize.py:20` 的 `_REF_PATTERN` 以 `\s*...\s*` 匹配参考文献编号，剔除时连单词间空格一起吞掉（`see [12] page`→`seepage`）。现有测试 `test_vocabulary.py:97` 只断言 `"sentence" in cleaned[0]`（`Goodsentence` 也含 substring），**掩盖了缺陷**。
2. **pdf_ingest 空文本不降级**：`pipeline/pdf_ingest.py:95` `if pm:` 只判非 None 不判文本非空。实测构造文本全落在页眉 8% 区（y<0.08h）的 PDF：`_try_pymupdf` 返回空文本 dict → 判定成功 → 不再降级 pypdf → raw_corpus 为空 → 后续 4 阶段全失败（`ok:False`，仅 pdf_ingest 完成）。三级降级在此场景失效。
3. **弱模式空词汇表**（与缺陷 2 叠加更严重）：无 LLM 时，离线 CEFR 词表仅 265 词 → `gloss_bilingual` 几乎全空 → `field_renderers.py:145` L1 门过滤全部词条 → **`generate_vocabulary` 返回 `ok:True` 但产出零词条 HTML**，用户无法感知失败。建议：`ok` 判定增加"entries_count>0"条件，或接线 ecdict 提供离线释义兜底。
4. **phen-tag 正式产物缺失**：`render/field_renderers.py:108` 的 phenomena 渲染实测有效（entry_to_html 含"熟词生义"标签），但正式产物（生命现象学 ielts6.5）中 `phen-tag`/`熟词生义` 计数为 0——现象识别结果未进入该批正式产物（需回溯该产物的 enrich 阶段是否写入 phenomena，代码路径本身存在）。
5. **README 测试数过时**：README 声称 60/60，实测 154/154（与 CHANGELOG 148 一致）。

## 六、判定结论

### 是否达同类顶尖？——**核心管线达顶尖，整体未完全达标**

**已达顶尖（有真实实现+实测证据）**：
- 全流程管线（提取→清洗→分位筛选→补全→渲染）真实可跑，5 阶段端到端实测通过
- **差异化亮点超越对标**：统一难度分位引擎（混合 Q）、词形归一化屈折/派生策略、多词库冲突消歧、三道闸防失控筛选、语义显著词保护——这些是 Vocabu/单词鸭未见的工程化设计
- MCP 10 工具 + 标准化 schema 契约（等价 tools/list+call）
- 正式产物质量（5976 词条全字段、模板渲染、book_sense"本书含义"）已达对标水准
- 154/154 测试全绿（含 6 项 web 测试）

**未达标（如实列出的缺口）**：

| # | 缺口 | 对标项 |
|---|---|---|
| 1 | **Word(.docx) 导出不存在**（基线诚实标注①未补） | V-05 |
| 2 | **图像 OCR 不存在**（②未补，仅文本层断裂修复） | V-01 |
| 3 | **ecdict/cefrj/octanove/lemma.en 未接线**（③未补，弱模式释义缺失根因） | V-02 |
| 4 | **OCR 断裂恢复率 ≥95% 无量化测试集**（仅 2 项示例测试） | V-01 |
| 5 | **附件缺"短语句式统计"**（4/5 类） | V-04 |
| 6 | **前端无词条浏览/多维度筛选/语种选择**（最小闭环而非完整闭环） | V-07 |
| 7 | 例句清洗粘连 bug、pdf_ingest 空文本不降级、弱模式空词汇表 ok:True 假阳性 | 新发现 |

**总体判定**：作为 **Python 库 / MCP 插件**（管道 + 生态 + 测试）达同类顶尖；作为**完整产品（含网页端闭环 + 导出格式全谱）** 未完全达标。优先补缺顺序建议：③接线 ecdict（一行修复弱模式空表）→ ①Word 导出 → ⑥前端词条浏览 → ④恢复率测试集 → ⑤短语句式统计 → ②图像 OCR（投入最大，若目标用户群是扫描书可延后）。
