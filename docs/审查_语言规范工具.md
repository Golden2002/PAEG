## 二、重点核查（任务指定四项）

### 1. 三级校对体系 —— 仅语法级真实，基础级/语义级缺失

- **基础级（错别字/标点/格式）**：错别字规则 **0 条**（无任何形近字/音近字/易错词表）；格式规则 **0 条**；标点仅 2 条（`rule_registry.py:276-303`，其中 1 条为通则性 prompt 而非可检测规则）。对标要求 ≥50 条，实际 **2 条**，缺口 96%。
- **语法级**：真实、完整、可用。`rules.py:46-155` 52 条正则 + `rules_enhanced.py` 三条通则（词法完整/句法完整/充分状语）+ `rule_registry.py` 16 条内置（通则 3 + 列举 13）。实测 5 类样例全部正确命中（见 §三.2）。
- **语义级**：缺失。既无规则通道（逻辑矛盾连接词检测/概念混淆/歧义指代），也无 LLM 双通道（无 semantic_checker）。
- **三级独立开关**：缺失。唯一开关是 `gate.py:29` 的 `apply_l2`（布尔），无 basic/grammar/semantic 分级开关，无分级报告（A4 未落地）。

### 2. 术语白名单保护 —— 缺失（方向恰好相反）

- 现有词表机制 `forbidden.py` 是**禁词黑名单**（禁 AI 腔/网络用语，552 项内置 + JSON 可扩），其作用与"术语保护"**相反**：黑名单是"禁止出现"，白名单是"禁止误改"。
- `docs/02_顶尖标准对标表.md:23` 基线行已如实标注"🟡 有词表机制但无'术语保护'语义"——**该差距至今未补**。术语误改率 0 无任何测试断言。

### 3. 修订痕迹 / 校对报告 —— 缺失（返回纯文本）

- 所有矫正入口（`gate_content`/`gate_short`/`polish_text`/`refiner.refine`）签名均返回 `str`（实测确认），无 `{pos, original, revised, reason, type}` 结构，无 diff，无问题类型统计报告。
- 设计文档 §3/§5（`docs/05_技术架构设计.md:52-60,80-88`）定义的 ProofreadResult 数据模型、`/api/proofread` 接口、trace_builder/report_builder 全部停留在设计稿，无代码。

### 4. MCP 三原语（tools/resources/prompts）—— 仅 tools 达标

- **tools（达标）**：实测 7 个工具全部注册且可调用（`test_mcp_server.py` 8 用例通过）；console 入口 `paeg-lang-style-mcp`（`pyproject.toml:18-19`）+ `python -m paeg_lang_style.mcp_server`（stdio）。
- **resources（缺失）**：实测 0 个。设计中的 `style_presets://`、`term_whitelist://`、`reports://` 均无。
- **prompts（缺失）**：实测 0 个。设计中的 `proofread_workflow`/`domain_adapt`/`report` 模板均无（现有 `build_style_prompt` 工具只是拼系统提示词字符串，非 MCP prompts 原语）。
- **调度嵌入**：函数级嵌入路径真实（见下）。

### 5. 嵌入其他工具输出流程的能力 —— 真实且已落地（唯一全项达标的能力）
