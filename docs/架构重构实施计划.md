# 架构重构实施计划（A-R1/A-R2/A-R3）

> 依据：架构评估报告（docs/架构评估报告.md）——三巨型文件（server.py 3541 / subagents.py 4484 / prompts.py 2805）是主要技术债
> 定位：P1 工程债（Oracle 裁定"不阻塞工具顶尖化，工具达标后偿还"）——四工具现已 23/23 门槛达标，本计划为后续偿还方案

## 一、重构目标

| 项 | 文件 | 现状 | 目标 | 风险 |
|---|---|---|---|---|
| A-R1 | subagents.py（4484 行） | 10 子代理集中注册与调度 | 拆分为 agents/ 目录（diagnostor/planner/presenter/evaluator 等各一文件） | 中（子代理签名不统一） |
| A-R2 | prompts.py（2805 行） | 35 学科 × 4 学段提示词集中 | data/prompts/ 配置化加载（prompt_loader 已有） | 中（提示词依赖上下文） |
| A-R3 | server.py（3541 行） | 生成器/工具函数驻留 | 下沉 services/（端点已蓝图化） | 低（纯函数下沉） |

## 二、分步实施计划

### A-R3（最低风险，先做）——server.py 生成器下沉
1. 识别 server.py 中的纯函数/生成器（teach_stream_gen 等）
2. 迁移到 services/ 对应模块
3. server.py 保留 import + 路由（薄壳）
4. 验证：pytest 全绿 + smoke_test

### A-R2（中风险）——prompts.py 配置化
1. 提取 LANGUAGE_STYLE / WEIL_CORE 等常量 → data/prompts/*.md
2. 35 学科提示词 → data/prompts/subjects/*.md（按学科目录）
3. prompt_loader 加载（已有缓存机制）
4. 验证：各学科提示词字节级一致

### A-R1（中风险）——subagents.py 拆分
1. 识别 10 子代理的类边界
2. 拆分为 agents/diagnostor.py 等
3. subagents.py 保留注册表 + 调度（薄壳）
4. 验证：10 子代理调用签名不变

## 三、验证策略（重构铁律）

1. **行为不变性**：重构前后 API 字节级一致（pytest 全绿 + smoke_test）
2. **Expand-Migrate-Contract**：先复制 → 迁移调用 → 删除旧代码
3. **ratchet**：只前进不后退（每步可回滚）

## 四、预估

- A-R3：1 天（低风险）
- A-R2：2 天（提示词配置化）
- A-R1：2-3 天（子代理拆分）
