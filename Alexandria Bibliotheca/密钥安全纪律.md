# PAEG 密钥安全纪律（Secrets & Credentials Security Discipline）

> **定位**：PAEG 的密钥/API/token/凭据泄露防护铁律与泄露后处置 SOP。
> **来源**：2026-08-23 真实泄露事故处置固化的经验（git remote 内嵌 token + 代码硬编码 API key + 文档粘贴 key + git 历史残留，四类问题一次全踩）。
> **被引用**：工程实践规范 §2.2「token 不入库」主引用；开发流程「阶段 4 环境 / 阶段 7 发布」强制检查项。

---

## 1. 四条铁律（优先级最高，违反即验收不通过）

| # | 铁律 | 说明 |
|---|---|---|
| 1 | **密钥一律环境变量** | 任何 API key / token / 密码只经 `os.environ.get("XXX")` 读取，代码、配置、文档中**禁止出现真实值** |
| 2 | **文档禁贴真实 key** | 技术说明/README/CHANGELOG/恢复指南等任何文档引用密钥时，一律用 `sk-***` 或 `sk-xxx…` 占位；例：`sk-e42960ce…` |
| 3 | **remote 禁内嵌凭据** | git remote URL 禁止 `https://user:token@host/...` 形式；凭据走系统凭据管理器（`credential.helper=manager`）或环境变量 |
| 4 | **提交前必扫描** | 每次提交前跑 `security_scan2.py` 复查；新出现真实密钥格式（ghp_/sk-/AKIA/AIza 等）即拦截 |

## 2. 真实事故复盘（2026-08-23 · 一次踩全四类）

> **案例价值**：这是本项目真实发生过的密钥泄露事故，四个泄露点各自对应一条铁律。

### 2.1 泄露点清单

| # | 泄露点 | 类型 | 对应铁律 | 处置 |
|---|---|---|---|---|
| 1 | 8 个仓库（主项目 + 14.1~14.6）git remote 内嵌明文 GitHub token（`ghp_…`） | remote 凭据 | 铁律 3 | 全部移除 → 凭据管理器接管 |
| 2 | `10_封闭测试/…/oracles.py` 硬编码 `API_KEY = "sk-…"` | 代码硬编码 | 铁律 1 | 改 `os.environ.get("DEEPSEEK_API_KEY")` |
| 3 | `关机后恢复指南.md` 粘贴了 Minimax + DeepSeek 两个完整 key | 文档泄露 | 铁律 2 | 脱敏为 `sk-***` |
| 4 | 上述 key 已随历史 commit 推送远程（`git log -S` 命中多个提交） | git 历史残留 | — | `git filter-repo --replace-text` 重写全历史 + force push |

### 2.2 根因教训

- **remote URL 内嵌 token** 是最隐蔽的泄露——它不进 git 历史、不进文件，只在 `.git/config`，但任何能读 `.git` 的人/工具都拿到完整 token。
- **文档顺手贴 key** 是"方便自己"的惯性（恢复指南写 key 便于恢复）——恰恰是最危险的。
- **硬编码 key 的代码文件** 一旦 `git add` 就永久进历史，改文件不够，必须清历史 + 轮换。

## 3. 防护清单（预防 · 每次交付前自查）

- [ ] 全仓库 `git grep -E "sk-[A-Za-z0-9]{20,}|ghp_[A-Za-z0-9]{20,}"` 无命中（排除占位符 your_/xxx/sk-***）
- [ ] 全仓库 `.git/config` 无 `@` 内嵌凭据（`git remote -v` 检查）
- [ ] `.env` / `auth.json` / `*.bak` 在 `.gitignore` 且历史中从未出现（`git log --all --oneline -- <file>` 空）
- [ ] `.env.example` 是占位符模板（`your_api_key`）
- [ ] 提交 message / CHANGELOG / 文档无完整 key
- [ ] 新增密钥 → 立即写入环境变量 + 记录在案，不落盘

## 4. 泄露后处置 SOP（检测 → 止血 → 根治）

> 发现泄露时按此顺序执行，**先止血再根治**。

### 4.1 检测（高效方法）

```powershell
# 工作区（只扫已跟踪文件，秒级）
git grep -l "sk-XXXXXXXX" 2>$null

# git 历史（-S 命中含该字符串的提交；大仓库可能慢，分仓库跑）
git log --all -S "sk-XXXXXXXX" --oneline

# 全面扫描脚本（文本文件限定，避免超时）
python D:\wbo-workspace\security_scan2.py
```

### 4.2 止血（立即脱敏 + 环境变量化）

1. 代码硬编码 → 改 `os.environ.get("XXX")`，提交
2. 文档/CHANGELOG 粘贴的完整 key → 脱敏为 `sk-xxx…`
3. remote 内嵌 token → 移除（见 §5.1）

### 4.3 根治（git 历史清理 · 标准流程）

> **首选工具 `git filter-repo --replace-text`**（git 官方推荐，比 filter-branch 快、比 BFG 免 Java）。Oracle 论证结论：重写历史 + force push + 轮换，三者缺一不可。

```powershell
# 0. 备份（--no-local 防硬链接被后续 gc 连累；mirror 保留全历史用于回退）
git clone --mirror --no-local <repo> <backup_dir>

# 1. 安装工具
pip install git-filter-repo

# 2. 写替换映射（LF 无 BOM，格式：原文本==>替换文本）
#    secret_replace.txt 内容：  sk-XXXXXXXX==>REMOVED_API_KEY
[System.IO.File]::WriteAllText("$env:TEMP\r.txt", "sk-XXXXXXXX==>REMOVED_API_KEY`n")

# 3. 重写全部历史（非 fresh clone 需 --force；会自动清空 remote 防误推）
git filter-repo --replace-text "$env:TEMP\r.txt" --force

# 4. 验证（历史 + 工作区均 0 命中）
git log --all -S "sk-XXXXXXXX" --oneline   # 应为空
git grep -l "sk-XXXXXXXX"                   # 应为空

# 5. 重建 remote + force push 双远程
git remote add origin https://github.com/OWNER/REPO.git
git push origin --force --all
git push origin --force --tags

# 6. 本地收尾（清除 reflog 与旧对象）
git reflog expire --expire=now --all
git gc --prune=now --aggressive
git fsck --no-reflogs --unreachable      # 应无不可达对象

# 7. 销毁含密钥的备份
Remove-Item <backup_dir> -Recurse -Force
```

### 4.4 轮换（唯一彻底根治）

> 历史重写**不保证**服务端彻底移除旧对象（旧 commit 可能仍凭 SHA 访问）。**撤销并重新生成密钥**是唯一根治。新 key 只放环境变量。

## 5. 具体操作参考

### 5.1 移除 remote 内嵌 token

```powershell
# 把 https://user:TOKEN@github.com/OWNER/REPO.git 改为无 token URL
git remote set-url origin https://github.com/OWNER/REPO.git
# 凭据走系统凭据管理器（已验证 credential.helper=manager 可用）
```

### 5.2 保护分支无法 force push 的处置

- **GitHub**：保护分支规则通常需在 Settings → Branches 关闭后 force push；或删除分支重建（`git push origin --delete <branch>` 后重新 push）
- **ModelScope**：默认分支（HEAD 指向）无法删除/强推——需在网页端「仓库设置 → 默认分支」改为新分支后，再删除旧分支

### 5.3 环境变量化标准写法

```python
# 安全写法（缺省空串，绝不写回退到硬编码值）
API_KEY = os.environ.get("DEEPSEEK_API_KEY", "") or os.environ.get("PAEG_DEEPSEEK_API_KEY", "")
```
