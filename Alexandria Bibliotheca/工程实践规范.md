## 1. Git 工作流

### 1.1 分支策略（Trunk-Based + 短生命周期）

```
main (永远可发布)
  ├─ feat/xxx (寿命<1天) → PR → CI → review → merge
  └─ hotfix/xxx (紧急) → 立刻合并
```

**规则**：
1. `main` 永远处于可发布状态
2. 分支寿命 < 1 天
3. 合并前必须有 ≥ 1 个 approval + 全部 CI 通过
4. 大特性用 feature flag 隐藏（未完成功能不直接上生产）
5. release tag 从 main 切出，遵循 SemVer

**不采用 GitFlow**：维护负担重，与 CI/CD 集成难（AWS 建议弃用）。

### 1.2 分支命名规范

| 前缀 | 用途 | 示例 |
|---|---|---|
| `feat/` | 新功能 | `feat/add-semantic-search` |
| `fix/` | bug 修复 | `fix/whisper-stt-fallback` |
| `refactor/` | 重构（行为不变）| `refactor/extract-concept-graph` |
| `docs/` | 文档 | `docs/tech-doc-v1.1.8` |
| `test/` | 测试 | `test/srs-sm2` |

### 1.3 Commit 规范（Conventional Commits）

```
<type>(<scope>): <subject>

feat: C3 语义检索(§3.54, P0)——渐进式架构(BM25Plus + BGE ONNX)
fix: 技术说明文档 PDF 渲染修复——围栏黏连19处
docs: 技术说明 v1.1.8 内容优化
test: C5 后端 Whisper STT 测试锁定
```

**项目惯例**：
- 中文 subject，带需求文档章节引用（§3.54）
- feat/fix/docs/test/chore 前缀
- 复杂 message 用临时 Python 脚本经 subprocess 提交（PowerShell 对 `<` `>` 重定向符解析有坑）

### 1.4 PR 规范

- **小 PR**：< 400 行变更（Google 建议）
- 标题：`<type>: <摘要>`
- 描述：做了什么/为什么/验证方法
- ≥ 1 approval + CI 全绿才合并

### 1.5 Merge vs Squash vs Rebase

| 策略 | 适用 | 说明 |
|---|---|---|
| Squash | 常规 feature | 单 commit 合并（历史干净）|
| Merge | 需要保留分支历史 | 保留 merge commit |
| Rebase | 线性历史 | 慎用（重写历史）|

## 2. 三处一致铁律

### 2.1 三处一致原则（本地 ↔ GitHub ↔ Release）

**项目维护铁律**：本地项目目录、GitHub 仓库（Golden2002/PAEG main 分支）、Release 三者内容必须完全一致、互为备份。

### 2.2 sync_check.py 使用

```powershell
python sync_check.py        # 只读校验
python sync_check.py --fix  # 自动推送差异（本地为权威源）
```

**原则**：
1. 本地为权威源——任何修改先在本地完成并验证
2. 每次变更后同步——改完代码/文档 → sync_check.py --fix 推送 GitHub
3. Release 保持最新——重大版本更新时更新 Release 名称与正文
4. 敏感数据不上传——users.json / users_data/ / uploads/ / data/ 等不参与备份
5. token 不入库——脚本从环境变量 GH_TOKEN 读取

### 2.3 双远程推送（GitHub + ModelScope）

| 通道 | 命令 | 时机 |
|---|---|---|
| GitHub | `python sync_check.py --fix` | 每批任务收口 |
| ModelScope | `git push modelscope master` | 每批任务收口 |

**判定**：sync_check "一致 X 文件 / 缺失 0 / 差异 0" + modelscope push 成功——不是可选项，是交付前置（纪律 34）。

## 3. 代码质量门禁

### 3.1 Lint / 静态分析配置

- audit_check.py：40 项 P0/P1（架构不变量）
- P0 铁律：`bare except: pass` 禁令
- P0 铁律：写端点缺 `_is_registered` 校验禁令

### 3.2 代码风格规范

- **引号铁律**（元能力 §5.5）：Python 字符串引号一致性
- 类型安全：禁止 `as any` / `@ts-ignore`（TypeScript）
- 250 行模块上限（超限拆模块）

### 3.3 测试套件分层

| 层 | 工具 | 时间 |
|---|---|---|
| 单元测试 | pytest tests/ | < 1 min |
| 静态审计 | audit_check.py | < 10 s |
| 冒烟 | smoke_test.py | < 30 s |
| E2E | Playwright | 按需 |
