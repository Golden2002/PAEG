## 1. 环境与流水线（对应开发流程阶段 4）

### 1.1 Docker 镜像构建（Dockerfile 逐层解析）

```
FROM python:3.12-slim            # 基础镜像（manim 0.19 兼容最优）
RUN apt-get install ffmpeg libcairo2-dev libpango1.0-dev ...  # 系统依赖（manim 渲染必需）
COPY requirements.txt .          # 依赖清单（缓存层优化）
RUN pip install -r requirements.txt + manim==0.19.0            # Python 依赖
COPY . .                         # 全部源码（server.py + 前端 + Library）
VOLUME [users_data, downloads, Library]   # 数据卷（运行时挂载）
ENV PORT=7860                    # 魔搭固定公网端口
EXPOSE 7860
HEALTHCHECK CMD python -c "urllib.request.urlopen('http://localhost:${PORT}/api/health')"
WORKDIR /app/05_实现原型
CMD ["python", "server.py"]      # 容器主进程
```

**关键设计决策**（ADR-005）：
- 单容器（非多容器编排）：部署简化优先
- 分层缓存：依赖 COPY 在源码 COPY 前
- HEALTHCHECK 指向真实端点 `/api/health`

### 1.2 本地开发 vs 魔搭部署对比

| 环境 | 端口 | 机制 |
|---|---|---|
| 本地 docker-compose | 5000 | compose `PORT=5000` 显式覆盖 |
| 魔搭创空间 | **7860（强制）** | 平台注入 PORT=7860；ms_deploy.json 声明 |
| 裸跑 server.py | 5000（默认） | config.py `APP_PORT = os.environ.get("PORT", 5000)` |

**魔搭端口规则**：Docker 类型强制 7860（平台把 7860 暴露公网）。监听其他端口 → 一直"部署中"。

### 1.3 ms_deploy.json（魔搭专用）

```json
{
  "$schema": "https://modelscope.cn/api/v1/studios/deploy_schema.json",
  "sdk_type": "docker",
  "resource_configuration": "platform/2v-cpu-16g-mem",
  "port": 7860
}
```

- `sdk_type: "docker"`：声明 Docker 部署（缺省按 gradio 处理 → 构建失败）
- docker 类型环境变量**不在 json 配置**——需创空间界面"设置→环境变量"手动配 DEEPSEEK_API_KEY

### 1.4 双远程仓库同步（GitHub + ModelScope）

**铁律**（纪律 34）：任何交付前双端同步。

| 通道 | 命令 | 说明 |
|---|---|---|
| GitHub | `python sync_check.py --fix` | API 通道，本地为权威源 |
| ModelScope | `git push modelscope master` | git 通道，oauth2 token 在 remote |

**判定标准**：sync_check 显示"一致 X 文件 / 缺失 0 / 差异 0" + modelscope push 成功。
**三处一致**：本地 ↔ GitHub ↔ Release（tag）内容一致，可从任一端恢复整个项目。

**注意**：
- 本地代理重置 git 协议 → GitHub 走 API 通道
- 敏感数据不上传：users.json / users_data/ / uploads/ / data/（.gitignore）

### 1.5 Docker 打包依赖纪律（纪律 33）

| 依赖类型 | 同步位置 | 实例 |
|---|---|---|
| pip 包 | `05_实现原型/requirements.txt` | onnxruntime / rapidocr-onnxruntime / faster-whisper |
| 系统库 | Dockerfile apt 段 | ffmpeg / libcairo（manim）|
| 模型文件 | Dockerfile COPY / 白名单 | bge ONNX（下载到 data/models/）|
| 可选重依赖 | requirements 注释 + 需求文档 | torch / pix2tex（防镜像膨胀）|

**验证**：改依赖后 `docker compose up -d --build` 必须成功。

## 2. 发布与版本管理（对应开发流程阶段 7）

### 2.1 SemVer 版本号规则

```
MAJOR.MINOR.PATCH（如 2.7.3）
MAJOR：不兼容 API 变更
MINOR：向后兼容新功能
PATCH：向后兼容 bug 修复
预发布：1.0.0-alpha.1
```

### 2.2 CHANGELOG 分类（Keep a Changelog）

`Added` / `Changed` / `Deprecated` / `Removed` / `Fixed` / `Security`——每版本一个 entry，最新在上，顶部 `[Unreleased]` 跟踪。

### 2.3 关键节点标记与回退流程

**节点识别标准**：功能上线/架构变更/行为变化。

**标记流程 4 步**：
1. 识别关键节点（功能/架构/行为变化）
2. 在技术全景文档对应章节记录
3. 更新 CHANGELOG + Release Notes
4. 双远程推送 + 三处一致校验

**回退 SOP**：Git revert 到上一 tag → 重新构建 → 部署 → 验证。

### 2.4 Release 与本地一致性（sync_check.py）

```powershell
python sync_check.py          # 只读校验（本地↔GitHub）
python sync_check.py --fix    # 自动推送差异（本地为权威源）
```

## 3. 运维与可观测性（对应开发流程阶段 8）

### 3.1 进程管理 SOP

```powershell
# 1. 查端口进程 PID + 启动时间
Get-NetTCPConnection -LocalPort 5000 -State Listen | Select -First 1
(Get-Process -Id $conn.OwningProcess).StartTime   # 与"最后启动时间"对比

# 2. PID 精确杀（不要只靠 Get-Process python——cmd start 子进程会漏）
Stop-Process -Id $conn.OwningProcess -Force

# 3. 确认端口释放
Get-NetTCPConnection -LocalPort 5000 -State Listen   # 应为空

# 4. 清 pyc + touch + 启动
Get-ChildItem -Recurse -Filter '__pycache__' | Remove-Item -Recurse -Force
(Get-Item server.py).LastWriteTime = Get-Date
Start-Process cmd -ArgumentList '/c','start /b python server.py > server_run.log 2>&1' -WindowStyle Hidden

# 5. 8 秒后验证端口进程启动时间 = 本次
```

**核心教训**："重启成功" ≠ "新代码生效"——必须看进程启动时间，不能只看 health 版本号。

### 3.2 日志在哪 / 常见问题速查

| 问题 | 排查 | 修复 |
|---|---|---|
| 服务没更新 | 进程启动时间 ≠ 本次 | 端口反查 PID + 精确杀 |
| 端口占用 | `Get-NetTCPConnection -LocalPort 5000` | 杀占用进程 |
| 魔搭一直"部署中" | 服务监听端口 ≠ 7860 | ms_deploy.json port=7860 |
| 前端能开 API 401 | 环境变量缺失 | 创空间界面配 DEEPSEEK_API_KEY |

### 3.3 故障 Runbook（残留进程）

**症状**：改代码后重启服务但行为仍旧（残留进程占端口，新进程静默失败）。

**诊断技巧**：
- 函数级 vs HTTP 差异 = 进程版本差异
- DEBUG 打印到怀疑函数第一行，日志无输出 = 服务器加载旧版
- `os.path.realpath` 会骗人——路径正确 ≠ 进程加载正确
- `Start-Process -RedirectStandardOutput` 会卡命令——避免使用
