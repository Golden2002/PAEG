# PAEG 架构可扩展性评估（Architecture Extensibility Assessment）

> **定位**：回答「PAEG 后续新增工具生态 / 安装 MCP 服务 / 安装 skills 能否方便扩展」这一问题的**证据驱动评估**。
> **方法**：源码落点逐层核对（config_hub / mcp_client / mcp_gateway / skill_registry / lang_plugin_bridge / 14.x 平级独立库 registry）+ 与 `架构评估报告.md`「工具生态适应性」结论对齐。
> **结论来源**：本评估不是新下判断，而是对 `docs/架构评估报告.md`（L44/L58）「工具生态适应性：优秀，是核心壁垒」的**源码级复核与展开**。
> **日期**：2026-08-29

---

## 〇、结论速览

| 扩展类型 | 接入方式 | 成本 | 判定 |
|---|---|---|---|
| 新增工具生态（14.x 独立库） | 平级目录放独立库 + 复制一个 5.5KB 桥接适配层 | 一次性薄适配 | ✅ 零主项目侵入 |
| 安装 MCP 服务 | `mcp_servers.json` 加一条 → `reload_all()` | 零代码 | ✅ 配置即生效 |
| 安装 skills | 丢一个含 `SKILL.md` 的目录（三层优先级） | 零代码 | ✅ 自动发现 |

**一句话结论**：PAEG 在「更新工具生态 / 装 MCP / 装 skills」三件事上都是**低摩擦、零代码侵入（除一次性薄桥接外）**的，扩展性是其少数真正「优越」的能力，且**有真实源码落点支撑，不是纸面设计**。

## 一、三条扩展路径（源码落点）

### 路径 1：新增工具生态 —— 14.x 平级独立库 + 唯一适配层

14.1~14.6 每个都是**平级独立库**（各自带 `mcp_server.py` + 独立 git 远程），靠**唯一适配层**接进主项目：

- **桥接范本** `05_实现原型/infra/lang_plugin_bridge.py`（5.5KB）：
  - 插件优先 + 静默回退：先 `import paeg_lang_style`，失败回退 PAEG 原实现（`services/lang_gate.py`）——**永不破坏原代码**（"千万不要破坏代码和文件"铁律的工程化兑现，见文件头注释 L10）。
  - 对外 API 与主项目调用点签名对齐（gate_content / fix_known_gaffes / check_ellipsis / get_style_prompt / make_refiner…）。
- **物料桥接** `05_实现原型/services/material_bridge.py`（6.9KB）：物料插件双轨接入。
- **独立库内部自我扩展机制**：
  - 词汇表 `14.3` 的 `registry.py`：`inject / register / execute` + `register_generator / register_language`（语种可扩展）。
  - 语言规范 `14.1` 的 `rule_registry.py`：`RuleRegistry.load() / watch()` 规则外置 JSON **热加载**。

> **新工具接入成本** = 平级目录放独立库 + 复制一个 5.5KB 桥接适配器（有现成范本），主项目零改动。

### 路径 2：安装 MCP 服务 —— 改一行 JSON，reload 即生效

`05_实现原型/mcp_client.py`（L6、L54-59、L133-143）：

- 读根目录 `mcp_servers.json`，声明标准 MCP server（**stdio + npx，与 opencode 同款格式**）。
- `connect_all()` / `reload_all()` 动态连接，**新增 MCP = JSON 加一条 + reload，零代码侵入**。

反向也通：`05_实现原型/mcp_gateway.py` 的 `build_mcp_server()` 把 PAEG 自己的工具（web_search / verify_math / generate_handout / generate_ppt…）暴露成**对外独立 MCP server**（`start_mcp_server(port=8765)`）——PAEG 既能「装」也能「被装」。

### 路径 3：安装 skills —— 丢一个 SKILL.md 目录

`05_实现原型/skill_registry.py`（L3-19）对标 **Anthropic Agent Skills 开放标准**：

- 三级渐进加载：L1 元数据（启动注入目录）→ L2 指令（匹配后加载正文）→ L3 资源（按需读脚本）。
- **三层优先级**：全局 `skills/` < 项目 `config/skills/` < 用户 `~/.paeg/skills/`（高优先级同名覆盖低优先级）。
- 新增 skill = 丢一个含 `SKILL.md` 的目录，自动被发现注册。

## 二、统一出口：config_hub（为什么「方便」）

`05_实现原型/config_hub.py`（L8-19）是统一配置中心，持有 mcp / skills / hooks / workflows / 内置工具五类子模块：

- `get_all_tool_defs()` —— LLM 看到的工具清单（统一出口）。
- `execute_tool(name, args)` —— 执行派发（统一入口）。
- `reload_all()` —— 动态重载全部配置（**改配置即生效，无需重启**）。

配置落点一览（全部实测存在）：

| 扩展对象 | 落点 | 说明 |
|---|---|---|
| 外部 MCP 服务 | `05_实现原型/mcp_servers.json` | stdio / npx / url |
| 内部工具声明 | `05_实现原型/config/mcp_tools.json` | 配置驱动，改文件不改代码 |
| skills | `config/skills.json` + `config/skills/` | SKILL.md 三层优先级 |
| hooks | `config/hooks.json` | {event, module, function} |
| 声明式 workflow | `config/workflows/*.json` | DAG：steps + depends_on |
| 子代理 | `config/agents.json` + `config/subagent_graph.json` | 子代理注册与图 |

## 三、两个务实的摩擦点（不粉饰）

1. **两条 MCP 路径要选对**：内部工具走 `mcp_tools.json`（注册 `tool_registry` 模块函数），外部服务走 `mcp_servers.json`（stdio 进程）。新工具作者得先分清「这是 PAEG 的内置函数，还是独立 MCP server」。
2. **14.x 独立库仍需一个薄适配层**：`lang_plugin_bridge.py`（5.5KB）/ `material_bridge.py`（6.9KB）是「每工具一个适配器」的模式，不是零适配——但适配层很薄、有现成范本可复制，成本是一次性的。

## 五、一句话总结

> **PAEG 的扩展性 = 「一切皆插件」DSH 式架构的落地**：14.x 平级独立库（唯一适配层桥接）+ MCP 双向（mcp_client 装 / mcp_gateway 暴露）+ skills 三层渐进披露 + config_hub 统一出口 + 改配置即生效。新增工具/MCP/skill 均为低摩擦、零代码侵入，是 PAEG 架构**最成熟、最可复用**的一面。
