# Memo 006 · 移动端 APP 探索（技术难度与可实现性）

> 性质：项目备忘（memo）· 产品形态探索

## 〇、背景与动机

PAEG 目前是 **Web GUI 形态**（单文件 index.html + Flask 后端），本地部署 + Cloudflare 隧道公网访问。随着项目成熟，探索移动端 APP 是自然的产品演进方向。

---

## 一、为什么做 APP（价值判断）

| 维度 | 说明 |
|---|---|
| **场景覆盖** | 学生/家长主场景在手机（碎片时间学习、随时倾诉、通勤复习）|
| **触达效率** | APP 常驻桌面/通知推送，优于浏览器书签 |
| **离线能力** | 语音（TTS/STT）、本地缓存、弱网可用 |
| **语音优先** | PAEG 已有语音模块，APP 形态更契合"语音对话教学"体验 |
| **付费路径** | 应用内订阅（IAP）是教育产品主流变现方式 |

---

## 二、技术路线选项（可行性由高到低）

### 选项 A：WebView 封装（最快，1-2 周）
- **方案**：现有 Web GUI 套壳（Capacitor / Tauri / PWA 打包）
- **技术**：`capacitor`（Ionic 出品）打包 index.html → iOS/Android 原生壳；或 PWA（Progressive Web App）直接可安装
- **工作量**：低（核心是配 manifest + 签名 + 上架）
- **能力**：语音（Web Speech API 已有）、推送（需补）、离线（需补 SW）
- **局限**：体验接近浏览器，深度原生能力（通知/后台/生物识别）需插件

### 选项 B：混合开发（3-6 周）
- **方案**：Flutter / React Native 重写前端 UI，复用现有后端 API
- **技术**：Flutter（跨平台 UI 一致性好）或 RN（JS 生态熟悉）
- **工作量**：中——index.html 的 SSE 流式渲染/语音/KaTeX 需逐一迁移
- **能力**：原生级体验、推送/支付/离线完善
- **局限**：前端 UI 全部重写（~4000 行 JS 的迁移成本）

### 选项 C：原生开发（8-12 周+）
- **方案**：Swift（iOS）/ Kotlin（Android）双原生
- **工作量**：高——两套代码、维护成本翻倍
- **能力**：最完整（后台语音、传感器、系统集成）
- **局限**：团队无移动端经验时风险最高

### 推荐路径（分阶段）
```
阶段1（验证）: PWA 先行（零成本验证移动端需求）
阶段2（提速）: Capacitor 封装成壳（1-2 周上架）
阶段3（深化）: Flutter 重写核心页面（体验对齐原生）
```

## 三、关键技术难点

| 难点 | 现状 | 风险 |
|---|---|---|
| **SSE 流式渲染** | Web 已有（fetch+reader）| 迁移到移动端需保流式体验（Khan 类教学逐字输出）|
| **语音（TTS/STT）** | Web Speech API + 后端 edge-tts | 原生端需换（如 Azure/讯飞 SDK），成本上升 |
| **KaTeX 公式** | Web 已集成 | 迁移 OK（跨平台库）|
| **离线/弱网** | 无 | 需补本地缓存 + 断点续传（教育场景网络差）|
| **推送通知** | 无 | 需接 APNs/FCM（复习提醒/老师跟进）|
| **数据安全** | 本地部署 | 未成年人数据合规（见 memo 001），APP 上架需隐私政策/备案 |
| **上架合规** | 无 | 国内安卓需软著+ICP 备案；iOS 需开发者账号（$99/年）|

---

## 四、可实现性结论

- **技术上完全可行**：核心逻辑（后端 Agent + 检索 + 教学闭环）与前端形态无关，移动端只是"换了个壳"
- **成本可控**：PWA/Capacitor 路径 1-2 周可出可安装版本；Flutter 重写 1-2 月
- **最大非技术挑战**：国内教育 APP 的合规（未成年人保护/备案/隐私），建议做前先咨询（联动 memo 001 数据安全）
