# 014 · 对话质量 P0 根因分析与修复（用户实测 + 对比文档）

> 日期：2026-08-11
> 触发：用户实测"难过"被路由到教学答非所问 + 提供两份对比文档
> （PAEG vs TutorOS 浮力教学 + 情绪支持 Agent 对接文档）。
> 关键认知：**LLM 判断优先、正则兜底**是设计原则——排查必须沿 LLM 判断链路，
> 不能只修词表（治标不治本）。

## 根因 1：情绪词"难过"被路由到教学（已修复）

**现象**：用户输入"难过"→ 收到"关于'难过'的讲解（视觉型/stepbystep）"元指令文本。

**根因链**：
1. teach_stream 的情绪门用 `paeg._affection_gate_check`（**纯词表**，paeg.py L640 含
   "好难过"但缺单字"难过"）→ 未命中 → 走教学
2. chat_stream 用 `is_affection_expression`（**纯正则**，meta_router.py L204 含"难过"）
   → 命中正常
3. **两处情绪门词表不一致 + 都无 LLM 判断**——违反"LLM 判断优先、正则兜底"设计

**实证**（route_intent LLM 判断）：
- "难过" → intent=emotion（conf=1.0）✅ LLM 完全正确
- "铁球为什么沉" → teach ✅ / "难过是什么意思" → answer ✅

**修复**：
1. `paeg._affection_gate_check` 情绪词表扩充（补"难过/伤心/委屈"等单字词）
2. **teach_stream 情绪门接入 LLM 路由**：`route_intent(concept, llm)` intent=emotion →
   走情绪支持（正则之上叠加，LLM 判断优先）
3. 验证：难过→情绪 ✅ / 铁球为什么沉→教学 ✅（不误伤）

**教训**：修"答非所问"必须先确认 LLM 判断是否正确（实测 LLM 一直正确），
错在**调用方没接入 LLM 判断**，只用了词表/正则。

## 根因 2：倾诉模式固定模板（未修复，P0 待做）

**现象**（用户文档）："我这次考试又没考好，我妈说我不如别人..."→ 固定回复
"我听见你说的了。我不急着给你答案...我在这儿陪着你。"

**问题**：
1. 只完成承接，无状态变化（多轮都是同一句话）
2. 未澄清事件/评价/感受的区别
3. 未进入行动选择

**期望（文档 §三）**：情绪支持闭环——悬置判断 → 澄清（开放式确认）→
分离事实与自我评价 → 重新行动（给选项）。每轮只推进一个状态，允许用户修正 AI 理解。

**方案**：AffectionSupportor 重写为**状态机**（承接→澄清→分离→行动），
每轮读取 `SESSIONS[affection_state_{uid}]` 决定下一步，不重复模板。
（工作量：1-2h，v0.46 内完成）

## 根因 3：教学"一轮讲完"不等学生（未修复，P0 待做）

**现象**（TutorOS 对比）：学生"我没看懂铁球沉轮船浮"→ PAEG 一轮输出
完整讲解+阿基米德原理+小测（3 段都讲完）。期望：**判断理解→一个教学动作→等学生回答→再下一步**。

**关键判断**（文档）："当前更像'一轮把课讲完'；目标是'判断当前理解 → 做一个教学动作 → 等学生回答 → 再决定下一步'"。

**方案**：
- 教学首轮：诊断卡点 + 只问一个问题 + 停下来等（不再全讲完）
- 后续轮：基于学生回答决定下一步（保留已讲内容记忆）
- 涉及 Presenter 输出策略 + teach_stream 流式节奏调整
（工作量：较大，v0.47 规划）
