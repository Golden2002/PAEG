## 一、重大教训：测试编码假象（浪费大量时间）

**现象**：连续多轮测试"检索返回 0 条/关键词乱码"，反复怀疑代码/Bing/LLM/缓存，
本地直接调用全部正常，服务器端全失败。

**根因**：PowerShell `Invoke-WebRequest` + `ConvertTo-Json` 发送中文 body 时**非 UTF-8 编码**
（GBK/ANSI），服务器收到 `??????????` 乱码 → jieba 切词失败 → 检索空。

**证据**：服务器日志 DIAG `q=??????????` 揭示乱码；改用 Python `urllib` + UTF-8 body 后
**5/5 全部通过**（光合作用 9/二次函数 10/红楼梦 9/自由落体 10/文艺复兴 7 条，全相关）。

**教训（入测试管线）**：
1. **凡测试中文 API 请求，禁止用 PowerShell ConvertTo-Json + Invoke-WebRequest**——
   必须用 Python urllib/requests + `ensure_ascii=False` + UTF-8 body
2. 服务器端怀疑"代码异常"前，先确认**请求编码正确**
3. 加临时 DIAG stderr 输出是定位服务器端问题的有效手段（print 到 stderr 不被 Flask 吞）
