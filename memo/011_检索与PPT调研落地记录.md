# 011 · 检索与 PPT 调研落地记录（v0.45）

> 日期：2026-08-11
> 触发：用户实测"联网检索/PPT 生成能用但不好用"——检索条数少且相关性差、PPT 无实质内容。
> 动作：librarian 调研业界最佳实践（26 条带来源建议）→ 落地到 web_search_tool.py。

## 一、调研核心结论（来源见正文标注）

### 检索
1. **多查询 K=2-3 为甜区**（4+ 只增延迟无 recall 增益）；小模型改写足够
2. **RRF 融合（k=60）**替代简单去重：score-agnostic，无归一化问题（OpenSearch 默认）
3. **URL 规范化**前置：去 tracking 参数/尾斜杠/www（实测去 30-60% 假重复）
4. **相关性打分**：核心词命中 + 标题匹配 + 内容长度 + 域名权重
5. **中文引擎**：SearXNG 自托管（ChinaSo+Bing+360）最优；博查/智谱需 key；Bing HTML 仅兜底
6. ⚠️ 反向证据：fusion 的 recall 提升会被 rerank 抵消 → 融合后必须二次精排

### PPT
7. **双阶段流水线**：LLM 大纲 → 逐页扩写（带前页上下文）——PPTAgent（EMNLP 2025）
8. **密度硬约束**：每页 ≤5 bullet、≤40 词、bullet ≤10 词、标题 ≤12 字
9. **speaker notes 承载详细解释**（正文只放短语）
10. **教育叙事**：导入 → 动机 → 核心概念 → 实例 → 小结 → 思考题

## 三、已知局限（需配置才能根治）

- **冷门中文专名**（如"西蒙娜·薇依"）：Bing 无解——被"西蒙电气/动画角色"污染。
  **根治**：配置 TAVILY_API_KEY / SERPER_API_KEY / BOCHA_API_KEY（代码 failover 已支持，
  key 存在时自动优先），或部署 SearXNG 自托管（ChinaSo 引擎）。属部署配置项，非代码缺陷。
