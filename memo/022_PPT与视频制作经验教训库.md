## 一、内容要求（做什么）

| 要求 | 说明 |
|---|---|
| 行动式标题 | 每页标题是完整观点句（"当学生说'我撑不住了'——PAEG 会停下来"）|
| 一页一观点 | 每页只讲一个核心信息 |
| 差异化故事线 | 问题→方案→验证→愿景；核心差异化要"情绪冲击+可验证" |
| 真实数据 | 大数字 callout（30/30 达标、8 层约束、7 页 128s）|
| 实测原文 | 关键对话**完整原文**（100-200 字），不只截断 |
| 价值观去人名 | 展示世界观/价值观/伦理观体系，**不提具体人名**（私人设定）|

## 二、质量要求（做到什么程度）

| 维度 | 标准 |
|---|---|
| Read-Through Test | 全部标题朗读是连贯短文 |
| 每页视觉锚点 | 大数字/图标/图表，禁纯文字页 |
| 截图比例 | **必须按原始长宽比**（不拉伸）；竖屏截图放窄栏 |
| 密度 | 正文 ≤40 词/页，bullet ≤10 词 |
| 风格统一 | 模板配色（深蓝#0F2A52+金#E6A528），禁默认蓝 |
| 视频可播 | mp4 用 add_movie 嵌入（PowerPoint 内可播放）|

## 三、微 agent 使用（怎么用）

| 要点 | 说明 |
|---|---|
| 委派 visual-engineering | 视觉工作必委派（配色/布局/QA 循环）|
| 素材要全 | 高清截图/对话原文/视频/参考文档一次给全 |
| 转图 QA 循环 | agent 必须转图→找问题→修复→复验（至少一轮）|
| 磁盘监控 | agent 渲染大文件吃磁盘（需先清理保障空间）|

## 四、画面要求（长什么样）

- 深色封面/收尾 + 浅色内容页（sandwich）
- 大数字 callout（60-72pt）
- 截图：裁剪/放大/高亮，小尺寸作凭证
- 视频页：嵌入可播 mp4 + 关键帧静态图展示（防空白）

## 五、易踩错误及根因（重点 ⭐）

### 错误 1：PPT 元素错位/重合/偏移
- **现象**：页面框/图形重叠、位置偏移
- **根因**：
  a) 插入新页后**原页索引偏移**（python-pptx 插入会 push 后续页），重建页用旧索引 → 改错页/覆盖
  b) 坐标硬编码未考虑实际内容长度（标题两行→文字溢出框）
  c) 截图显示框用**固定尺寸**未匹配原始比例 → 拉伸变形
  d) 添加形状后未更新后续元素坐标（相对定位失效）
- **预防**：插入后重新计算索引；截图按比例；QA 循环必查重叠

### 错误 2：截图比例扭曲
- **现象**：图片被拉伸变形
- **根因**：显示框宽高比 ≠ 原图宽高比（如 1725×2282 竖屏塞进方框）
- **预防**：先查原图尺寸，显示框按同比例（宽=高×(原宽/原高)）

### 错误 3：视频页空白（PPT 内）
- **现象**：视频嵌入后静态预览空白，只有标题
- **根因**：PPT 静态预览不渲染视频流（PowerPoint 内能播，导出/预览空白）
- **预防**：视频页加**关键帧静态图** + 说明每页内容；或加封面图

### 错误 4：视频帧只有标题没内容
- **现象**：视频画面每页只有标题，要点区空白
- **根因**：演讲稿 JSON 只返回 title+narration，**无 key_points**；且 LLM 返回页数 > 大纲页数时
  `points = _slides[len(_out)]["points"]` 越界 → 空列表 → 帧空白
- **修复**（v0.53）：prompt 要求每页 key_points；LLM 返回优先于大纲
- **预防**：结构化输出必须校验关键字段；帧绘制依赖的字段要在 prompt 明确要求

### 错误 5：页码 chrome 与实际不符
- **现象**：页脚显示"12"但实际是第 13 页
- **根因**：插入新页后未更新重建页的页码硬编码
- **预防**：页码从实际索引计算，不硬编码

### 错误 6：价值观念人名
- **现象**：价值观页出现"西蒙娜·薇依"
- **根因**：参考文档直接用（私人设定）
- **预防**：价值观/世界观/伦理观**只讲体系**（注意力/扎根/善的有限），不写人名

## 六、视频生成 pipeline 易踩点（memo/021 补充）

## 八、错位/重叠根因深度分析（v0.53 量化诊断 ⭐）

### 8.1 量化证据（2026-08-11 python-pptx 逐页检测）

- **22 页中 19 页有重叠**（P11 教学 16 处 / P13 技术亮点 15 处 / P20 视频 14 处最严重）
- P11 单页 **57 个形状**（装饰性空形状 + 内容混杂）

### 8.2 根因链（三层）

1. **装饰形状数量失控**：单页 50+ 形状（圆点/编号/图标/框），大量**空形状**（无文字）堆叠在内容上——装饰挤占内容空间
2. **坐标硬编码无碰撞检测**：装饰元素坐标是**手写固定值**（如 y=6-7in），与动态内容（对话文本/编号）**未做相交检查** → 内容增长后必然重叠
3. **内容长度动态变化**：标题/对话原文换行后高度变化，但装饰坐标不随之调整 → 静态装饰压动态内容

### 8.3 为什么"摆不正"

- 不是单一元素错，是**布局系统缺失**：无"内容流 + 装饰层"分离，装饰与内容混在同一坐标系手写定位
- 每页单独手写坐标 → 换内容就重叠 → 需**重新设计布局系统**（内容区/装饰区分层，装饰用相对定位）

### 8.4 预防方法（写进生成 prompt）

- 单页形状 ≤20（含装饰）；装饰用**底层占位**（先画装饰再画内容）
- 内容元素**碰撞检测**：添加前检查与已有形状相交（面积 >30% 则调整）
- 坐标**相对化**：装饰锚定内容区边缘，不手写绝对坐标
- QA 循环必做**重叠检测**（python-pptx 逐页 bounding box 相交扫描）

## 九、v7 排版系统性修复（2026-08-12 ⭐ 新增）

### 9.1 文本框格式三件套
- auto_size = NONE（防撑破布局）
- word_wrap = True（中文换行）
- 微软雅黑 + eastAsia + 行距 1.15 + 段后 3pt

### 9.2 markdown 清理三层坑
1. 正则要 flags=re.S（跨行匹配）
2. 跨 run 符号必须逐 run 清
3. tf.clear() 重建丢格式 → 优先逐 run 改文本

### 9.3 L0-L7 阶梯图对齐
- 层间距均匀（0.5in）
- 背景条/标签/描述同 top 对齐
- 用户喜欢旧设计 → XML 级整页替换（deepcopy + append spTree）

### 9.4 文字归位算法
中心点 → 找最大包含背景 → 对齐中心 → snap 0.1in 网格

### 9.5 页码页脚残留
页码 = 实际索引计算，不硬编码；版本号随更新

### 9.6 越界检测
- COM Slide.Export → PIL 检查边缘
- 品牌深蓝页脚是误报源（需区分）
- 几何检测（bottom > 页高）比像素可靠

### 9.7 心法
- 自动修复会引入新问题 → 每步修复后重新检测
- 以 COM 渲染为准，几何估算仅供参考
- 对话原文若源头只有 200 字，PPT 无法补全 → 数据采集阶段存完整

## 十、成熟 PPT 排版方案调研（2026-08-12 ⭐ 联网调研）

**来源**：Presentation Zen（Garr Reynolds）、Deckary 300+ 咨询/投资 deck 分析、Presentations.AI、Slidebazaar 网格系统、python-pptx 官方文档。**核心：PPT 排版不是艺术天赋，是系统性规则的纪律执行。**

### 10.1 五大基础原则（CRAP 变体）
1. **对齐 Alignment**：所有元素对齐到隐形网格（Arrange > Align），差几像素就显乱
2. **对比 Contrast**：大小/颜色/粗细强差异，一眼看清主次
3. **重复 Repetition**：同类型元素（标题/图标/页码）全 deck 一致
4. **留白 Proximity/Whitespace**：15-20% 页面留空；相关元素靠近、无关远离
5. **一致性 Consistency**：同字体/同颜色/同边距/同标题字号——slack 感来自不一致

### 10.2 网格系统（Grid System）
- 12 列网格（可拆 1/2/3/4/6 份）
- 页边距 = 宽度 5-10%；列间距（gutter）10-20px
- 所有元素：文本起点/图片尺寸/图表边界 = 对齐到列边界
- 跨页固定元素（标题/页码/logo）保持同一网格位置
- 正文 40-70 字符/行（舒适阅读长度）

### 10.3 字号规范（投屏底线）
| 层级 | 字号 | 用途 |
|---|---|---|
| 标题 H1 | 36-44pt | 封面/章节 |
| 副标 H2 | 24-28pt | 小节标题 |
| 正文 | 18-22pt | 主内容（投屏底线 18pt） |
| 脚注 | 12-14pt | 说明/来源 |

**规则**：标题比正文大 ≥50%；正文 <18pt 就拆页（用户已授权"翻页换页"）；强调用粗体不用斜体/下划线

### 10.4 配色与字体
- ≤3-5 色（主色/辅色/强调色 + 中性背景）
- ≤2 种字体（标题 1 + 正文 1，无衬线优先——投屏衬线发虚）
- 文字对比度 ≥4.5:1

### 10.5 python-pptx 官方防溢出（关键 ⭐）
- `text_frame.fit_text(max_size=18)`：设置 NONE + word_wrap + **自动缩字号到适配**——长文本官方解法
- `auto_size = MSO_AUTO_SIZE.TEXT_TO_FIT_SHAPE(=2)`：字号自动缩小适配框
- `auto_size = NONE(=0)`：文字可自由溢出（需手动控字数）
- 手动控字号 + 拆页是"预排版"，fit_text 是"自适应"——**附录对话框用 TEXT_TO_FIT_SHAPE 最稳**

### 10.6 版面模板（8 种常见布局）
标题页/章节分隔/两栏对比/数据+洞察(60:40)/通栏图/对比框/议程/金句页——每种有固定模式，新页从模板起，不白板起

### 10.7 落地到本项目
- 建立**网格常量**：MARGIN=0.5in、GUTTER=0.3in、COL_W=(13.33-1.0-5*0.3)/6≈1.8in（6列）
- 附录对话框统一 `TEXT_TO_FIT_SHAPE` 防溢出
- QA 检查表：对齐/字体/颜色/对比度/留白 5 项（§18.4 已有 7 条，合并）

## 十三、v8 多媒体与合并四大坑（2026-08-12 ⭐ 必读）

### 坑1：pptxgenjs addMedia 视频不兼容
- 生成 PPT PowerPoint 打不开（单独测试也失败）
- 解决：**禁用 addMedia，用 python-pptx add_movie()**（官方支持）
- 流程：pptxgenjs 生成无视频版 → python-pptx 插入视频

### 坑2：pptxgenjs addImage SVG 损坏
- SVG 被生成 PNG+SVG 双文件，关系损坏
- 解决：**pptxgenjs 只用 PNG**，SVG 先用 sharp 转 PNG（256px 起）
- 铁律：pptxgenjs 禁 SVG

### 坑3：python-pptx 合并含图片 PPT 损坏
- deepcopy(shape XML) 不迁移图片 rels → 打不开
- 解决：**PowerPoint COM InsertFromFile 合并**（官方处理关系）

### 坑4：视频帧/编码
- 帧提取：imageio_ffmpeg.get_ffmpeg_exe() + `-ss N -frames:v 1`
- 兼容编码：libx264 baseline + yuv420p + faststart + aac 128k
- 每步生成后 COM 验证（Presentations.Open 是最终裁判）

### 排版保证体系
视频=python-pptx add_movie / 图片=PNG only / 文字=pptxgenjs精确坐标 / 对齐=统一y常量 / 合并=COM / 长文本=估算拆页
