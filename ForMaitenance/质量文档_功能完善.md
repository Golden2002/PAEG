## 2. 功能可达性：每个功能 LLM 端到端真的能用

### 2.1 质量标准

可达性分 4 级：

| 级别 | 含义 | 验证方式 |
|---|---|---|
| **L0 不可达** | 路由存在但 LLM 调不到工具 | 直接调 LLM with tools=[] 测试 |
| **L1 路由可达** | 路由能命中 | `curl` 200 |
| **L2 LLM 可达** | LLM 在 function calling 里能看到工具 schema | 检查 system prompt 注入 |
| **L3 端到端跑通** | 用户一句话 → LLM 决策调工具 → 工具返回 → LLM 综合 → 用户拿到结果 | 真实对话测试 |

**量化判定**：每个对外工具至少达到 **L3**；核心教学功能必须 L3。

> **业界锚点**：Integration Testing（集成测试）+ End-to-End Testing。Google "Testing Pyramid" 要求"少量 E2E 覆盖关键路径，大量单测覆盖组件"。

### 2.2 PAEG 项目经验

**已达 L3（端到端跑通）**：
- 教学 6 模式：teach / chat / answer / method / knowledge / affection 全部经 `meta_router.route_intent` + LLM 综合判断分流（`subagents.py` 配合 `_safe_chat_with_retrieval`）。每模式有完整链路。
- PPT 生成：`pptx_mcp_server.py` 经 `web_search_multi` → LLM 出大纲 → python-pptx 排版 → 下载。
- 用户文件 4 能力：触发词匹配 + BM25 检索 + handler → LLM 综合，4 个 handler 全到位。
- TTS：`/api/voice/tts` 经 edge-tts 输出 MP3。

**已达 L2（LLM 可见）但 L3 风险**：
- **工具调用执行循环**（`subagents.py` L462–L529 `_execute_tool_calls`）——README v0.45 提到"E2E 修复：answer 端点 500"，意味着曾因 LLM 返回 `tool_calls` JSON 未执行而 500。修复后能否稳定 L3？需持续 E2E 监控。
- **联网检索 `web_search_multi`**（L987–L1023）——`web_search_tool.web_search_multi` 依赖 LLM 联想查询词，LLM 偶发返回"问题不明确"等垃圾关键词（L204–L210 已加过滤），但端到端成功率待测。
- **Presenter 暴露工具给 LLM**（`subagents.py` L834–L839 `from tool_registry import get_tool_defs; _tools = get_tool_defs()`）——LLM 在讲解时可以调外部工具补内容，但**调用成功率 / 工具选择准确率**未量化。

**待达 L3**：
- **学习计划 study-planner**：skill 注册了但端到端"制定一周学习计划"是否真输出可执行计划？需 E2E 测试。
- **PDF / docx / xlsx skills**：作为"下载类 skills"，只在 LLM 决定写文件时触发；端到端"用户说'导出 PDF'→ 真有 PDF 文件"链路需验证。
- **讲义生成**：借 `file_explain` handler 输出，**没有独立 skill**——可达性 = L2.5。

### 2.3 实施建议

1. **建立 `tests/e2e/` 套件**：每核心功能 1 个 E2E 用例（pytest + requests）：
   ```python
   def test_teach_e2e():
       r = requests.post(f"{BASE}/api/teach", json={"concept": "什么是熵", "subject": "physics", "learner_id": "test"})
       assert r.status_code == 200
       data = r.json()
       assert data["summary"]["avg_score"] > 0
       assert len(data["presentations"]) >= 3
   ```
   目标：30 个 E2E 用例覆盖 30 个核心功能点。

2. **LLM 工具调用成功率监控**：在 `_safe_chat_with_retrieval` 加埋点，记录"LLM 是否成功调工具 / 调哪个 / 失败原因"，写到 `observability.py`，每月统计成功率 < 95% 的工具标黄。

3. **建立"可达性矩阵" `docs/REACHABILITY_MATRIX.md`**：每功能标记 L0/L1/L2/L3，每月 review。

4. **录制"用户旅程测试"**：用 `playwright` 录 5 段端到端用户旅程（注册→提问→续问→情绪→总结），每次发版前重放。

## 3. 功能质量：每种产出（对话/讲义/PPT/视频/manim）的高品质标准

### 3.1 质量标准（按产出类型）

#### 3.1.1 对话回复（chat / teach / answer / affection 通用）

| 维度 | 标准 |
|---|---|
| **正确性** | 学科内容事实正确，公式/定理无低级错误 |
| **完整性** | 概念解释覆盖"是什么 / 为什么 / 怎么用 / 边界"4 层 |
| **语言规范** | 中文无错别字、语法通顺、介词规范（README §6 全局中文语言质量层） |
| **个性化** | 根据画像调整深度 / 风格 / 节奏（v0.24 Adapter 决策真生效） |
| **可读性** | Markdown 结构清晰；关键概念加粗；公式用 LaTeX |
| **可测试** | 任意回复可在 100 字内总结核心观点（黑盒摘要测试） |

#### 3.1.2 讲义（lecture）

| 维度 | 标准 |
|---|---|
| **结构** | 标题 → 学习目标 → 前置知识 → 正文（分章节）→ 例题 → 总结 |
| **长度** | 1–3 万字；可拆分 |
| **公式支持** | LaTeX；KaTeX 渲染（GUI 已支持） |
| **可下载** | Markdown + PDF 双格式 |
| **来源标注** | 知识库引用 / 联网引用 / 用户资料引用 区分清楚 |

#### 3.1.3 PPT

| 维度 | 标准 |
|---|---|
| **大纲合理** | 3–10 页（默认 5–8 页）；章节有标题 + 关键点 |
| **排版美观** | 字号一致；正文 vs 标题有层次；配色不刺眼 |
| **内容精炼** | 每页 ≤ 50 字要点 + 1 张图 |
| **可下载** | `.pptx` 格式（python-pptx 生成） |
| **可选配图** | 可选自动配示意图（matplotlib / mermaid） |

#### 3.1.4 视频（video）

| 维度 | 标准 |
|---|---|
| **时长** | 30 秒 – 5 分钟（短讲解为主） |
| **分辨率** | ≥ 720p |
| **音频** | 中文 TTS 配音（edge-tts 已就绪） |
| **字幕** | 自动字幕（asr / whisper） |
| **结构** | 引入 → 主体 → 总结三段 |

#### 3.1.5 Manim 数学动画

| 维度 | 标准 |
|---|---|
| **时长** | 10 秒 – 2 分钟 |
| **清晰度** | 1080p @ 30fps |
| **概念对应** | 1 个动画 = 1 个核心概念 |
| **渲染速度** | 单段 ≤ 60 秒（开发期） |

> **业界锚点**：ISTQB 测试标准的"非功能测试"——可用性、可读性、可访问性。教学材料的"信息架构 IA"（Rosenfeld & Morville）。

### 3.2 PAEG 项目经验

**对话质量（最成熟）**：
- `subagents.py` L740–L757 三层教学模式（easy / normal / deep）LLM 自动判断，按用户意图调整讲解深度。
- `subagents.py` L785–L810 Adapter 决策注入（`switch_style` / `reinforce_note`）——上一轮评估发现"讲得不够好"，本轮自动追加指令让 LLM 改写。**这是 PAEG 的核心质量保证机制**。
- `services.polish._polish_text`（`server.py` L70 引用）——三层语言规范（L1 提示词约束 / L2 规则 / L3 LLM 修正），README v0.21.8 实测"倦→疲倦"修复。
- `language_refiner` 模块（README §6）独立能力，确保中文语法 / 介词 / 词法完整。

**讲义质量（凑合）**：
- 没有独立 `lecture_generator` skill；目前借 `file_explain` handler 输出 Markdown 风格内容。
- 知识库检索结果能注入（`_pre_retrieve`）但**未结构化成讲义模板**。

**PPT 质量（中等）**：
- `pptx_mcp_server.py` + `web_search_multi` 自动联想 4 查询词 → 12 条结果 → LLM 出大纲 → python-pptx 排版。
- 优势：来源丰富、内容精炼；不足：**未配图**，纯文字 PPT。

**视频 / Manim（缺失）**：
- `PAEG-Manim-Research/` 目录有调研材料，但**未接入运行时**。

### 3.3 实施建议

1. **建立 `agents/quality_checker/` 子代理**：对每个生成产物跑"质量自检"——检查对话正确性、讲义结构、PPT 页数 / 字符、视频时长 / 分辨率。**输出质量分**，低于阈值（如 0.6）触发重生成或人工提示。

5. **PPT 自动配字幕**：PPT 讲稿模式下自动生成讲者备注（speaker notes），导出 PDF 时嵌注释。

## 4. 边界处理：空输入 / 异常输入 / 超长输入

### 4.1 质量标准

| 输入类型 | 标准 |
|---|---|
| **空输入** | "" / null / 全空格 → 返回 400 + 友好提示，不 500 |
| **超短输入** | 1–2 字（如"你好"）→ 走闲聊 / 寒暄拦截，不进教学 |
| **超长输入** | > 5000 字（如粘论文）→ 截断 + 提示；或走复合输入检测（v0.21.9） |
| **非法字符** | 含 SQL 注入 / 脚本注入 → 安全过滤（`safety.guard_input`） |
| **敏感词** | 含自伤 / 自杀 / 暴力 → 情绪危机协议（README §7 危机协议） |
| **跨学科** | 物理问题标"高中政治" → 自动切换学科（Steering） |
| **跨学段** | 小学问题标"考研" → SSE 推"需切换学段"反馈 |
| **未收录学科** | "量子场论"等 → 反馈"暂未收录"，同时记录需求 |
| **无权限** | 未登录访问受保护资源 → 401 / 403 |
| **LLM 失败** | API 限流 / 超时 → 自动降级到规则模板，不 500 |
| **并发冲突** | 同一用户多端提问 → SESSIONS 锁 / 串行化 |

**量化判定**：边界测试覆盖 ≥ 10 类异常；每类至少 1 个端到端用例。

> **业界锚点**：ISTQB 边界值分析（BVA）、等价类划分、错误猜测法。OWASP Top 10 输入验证。

### 4.2 PAEG 项目经验

**PAEG 已有边界处理（按强度排序）**：

| 边界 | 处理位置 | 强度 |
|---|---|---|
| **空 / 异常输入** | 多处 `if not concept: return ...` + `try/except` | ✅ 中 |
| **超长输入** | `meta_router.is_intent_with_material`（`server.py` L736）检测长文 → DeepSeek 结构化分隔 | ✅ 优（v0.21.9 防注入） |
| **敏感词** | `safety.guard_input`（`server.py` L1050）拦截 → 走 emotion 分支 | ✅ 优 |
| **跨学科** | `services.steering._steer_subject`（L71 import）自动覆盖 | ✅ 优 |
| **跨学段** | `_steer_subject.grade_blocked`（L974）→ SSE 提示 | ✅ 优 |
| **未收录学科** | `_steer_unknown_response`（L1000）→ 用户友好反馈 + 记录需求 | ✅ 优 |
| **元问题** | `meta_router.is_meta_question` / `is_greeting` | ✅ 优 |
| **情绪危机** | `paeg._affection_gate_check`（L934） + 危机协议 README §7 | ✅ 优（v0.46 修复） |
| **LLM 失败** | `_safe_chat` 返回 `None` → 上层回退规则模板；`_consume_token_budget` 预算门 | ✅ 优（v0.46 P0） |
| **Tool 调用失败** | `_execute_tool_calls` try/except → 输出失败信息而非 500 | ✅ 优（v0.45 P0） |
| **工具调不到** | tool_defs 由 `tool_registry.get_tool_defs()` 集中提供 | ✅ 中 |
| **并发冲突** | `_LOGIN_LOCK`（`server.py` L91）+ SESSIONS dict | ⚠️ 部分（多进程不安全） |

**待补强**：
- **空输入**：当前部分路由用 `request.get_json(force=True)` 然后 `data["concept"]`——若前端传空会抛 KeyError。需统一校验 `if not data.get("concept"): return 400`。
- **并发冲突**：`SESSIONS` 是进程内 dict；多 worker / 多机部署会丢会话。需迁移到 Redis / 共享存储。
- **未登录访问**：当前 `_is_registered` 校验部分端点有（`server.py` L275、L848），但**并非所有写端点都有**——`audit_check` 应抓此 P0。

### 4.3 实施建议

1. **统一入口校验中间件**：在 `server.py` 加 `@app.before_request` 校验所有 POST 请求必填字段；缺字段返 400 + JSON 提示，不进路由。
2. **并发 SESSIONS 迁移**：Phase 3 把 `SESSIONS` dict 迁到 `infra/cache.py`（Redis 优先 / 进程内 fallback），接口保持一致。
3. **边界测试集 `tests/boundary/`**：覆盖 10+ 类异常输入（空 / 超长 / 注入 / 敏感词 / 跨学科 / 跨学段 / 未收录 / LLM 失败 / 工具失败 / 并发），每类 1+ 用例。
4. **fail-safe 默认**：所有 try/except 末尾 `logger.exception()`，保证失败有日志可查（`audit_check` 应禁 `except: pass`）。
5. **rate limit**：`flask-limiter` 加 IP 级限流（60 req/min）+ 用户级限流（10 req/min）；防滥用 / 防成本失控（参考 v0.46 token 预算门）。
