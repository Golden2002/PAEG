## 一、对话生成质量

对话是 PAEG 的核心产出，覆盖三种场景：学科教学讲解、生活闲聊、情绪倾诉。每一类都需要独立的质量标准与可验证指标。

### 1.1 教学讲解（学科教学主路径）

#### 质量标准（可量化）

| 维度 | 指标 | 达标值 |
|---|---|---|
| **结构清晰度** | 是否包含"现象/直觉 → 概念 → 公式 → 例题 → 小结"五拍 | ≥4/5 拍齐全 |
| **深度适配** | 初中/高中/本科/考研四档深度与实际学段匹配 | 偏差 ≤1 档 |
| **例题质量** | 例题是否含"审题→建模→分析→列方程→求解→检验"六步 | ≥5/6 步齐全 |
| **方法论呈现** | 物理/数学等学科是否含通用解题方法论 | 必须有 |
| **错误概念防御** | 是否显式提示常见误区（如 FCI 力学误区） | 至少 1 处 |
| **多表征** | 文字+公式+图示/类比三种表征是否齐全 | ≥2/3 |
| **数学公式合规** | 全部用 `$...$`/`$$...$$`（LaTeX）包裹，禁用中文/英文括号 | 100% 合规 |

#### PAEG 真实经验

`prompts.py` 的 SUBJECT_STYLES 字典里，物理（physics）和大学物理（college_physics）已落地的教学风格字段（v0.66+ 修复）：

- **method_guide**：物理解题通用方法论（审题建模→受力分析→坐标系→列方程→解方程+量纲检验→讨论物理意义）。
- **worked_example**：典型例题完整解答——以牛顿第二定律 2 kg/μ=0.2/F=10 N/求 3 s 末速度为范例，从建模到量级自检完整走通。
- **subfield_guide**：物理（中学版）六拍节奏 MOTTO→实验→建模→公式→验证→应用；FCI 常见错误概念显式防御。

`build_presenter_system`（prompts.py 第 1327 行起）已实现：
- 学段分层（`_GRADE_GUIDE`）：初中→高中→大学本科→考研，每档深度与语气单独定义（大学本科严格要求数学工具、推导思路、物理图景；考研侧重考点套路与得分效率）。
- 学科分支导航（subfield_guide）作为可选段，仅当本学科定义才注入。
- 学科教学法强化：数学走 CRA 三层（具体→表征→抽象）；外语走母语迁移（正迁移/负迁移/易错点）；哲学走概念分析与原文术语对照。
- 母语迁移块（NATIVE_TRANSFER_BLOCK）只对 `english/french/german/japanese/college_english` 五个语言学科注入，避免污染非语言学科。

#### 实施建议

1. **每条讲解前自动注入 `presenter_hint`**：从 `pedagogy.choose_strategy` 选教学策略（讲解/引导/探究/纠错）→ 注入 Presenter 的 system prompt → LLM 知道当前该用哪种节奏。
2. **物理/数学等学科必须配置 `method_guide` 与 `worked_example` 两个字段**，否则 LLM 退化为"念定义"模式。
3. **每学科的"常见误区"清单要明确写入 subfield_guide**，例如物理的 FCI 误区（"力是维持运动的原因"）。
4. **1500 字教学结构**：经 PAEG 多轮测试，单次讲解 1200-1800 字最优——过短显得空洞，过长学生读不完。建议每步不超过 300 字 + 留白 50 字。

### 1.2 闲聊（非学科话题）

#### 质量标准

- **不套教学模板**：用户问"今天天气怎么样"→ 不能强行进入教学流程讲"气象学知识"；应自然回应天气本身（meta_router 已通过 `_llm_route_intent` 优先判定为 non_teaching）。
- **多段消息 + 短句节奏**：用 `【NEXT】` 分隔 2-4 段，模拟"思考→补充→推荐"的真实对话流。
- **不抢主导**：用户只是想聊天，不要追问"想学什么"，除非他主动求教。
- **称呼节制**：偶尔用昵称，不每句都叫（prompts.py 第 188-192 行明确约束）。

#### PAEG 真实经验

`build_general_chat_system`（prompts.py 第 1818 行起）已实现：
- 模式结构化注入（v0.41.6）：前端 mode 是确定性信号，LLM 拿到"用户已选闲聊"后按对应场景角色回应，不必再判断意图。
- 注入 TRUTH_GROUNDING + WEIL_CORE 两层底线（人格 + 防幻觉）。
- 注入 BDI（信念/愿望/意图）与掌握度画像（v0.26 P0 修复）。
- 多段输出策略：前端按 `【NEXT】` 分隔错时显示。

#### 实施建议

1. **mode 信号是金**：前端已选闲聊时，server.py 必须把 mode 参数传给 build_general_chat_system，避免 LLM 误以为还在教学流程。
2. **闲聊输出的字数上限建议 800-1200 字**：过长会让用户失去"对话感"，过短显得敷衍。
3. **不要用"分析你""我感觉你"**：薇依式陪伴是先"安静感受对方处境"，而不是宣布"我在分析你"。

### 1.3 倾诉（情绪支持）

#### 质量标准

- **不教、不答、不解决**：情绪场景下 LLM 的任务是"注意力陪伴"，不是给方案（prompts.py 第 32-35 行 `_THINK_PREFIX_AFFECTION` 显式约束）。
- **危机信号必须先回应再关怀**：检测到自伤/自杀信号时，LLM 先完整回应用户说的话，再自然融入 12356 热线（不能机械短路成预制提示词）。
- **拒热线后不重复**：用户明确拒绝热线/服务后不再提示——尊重选择。
- **疏导 + 认知真实**：薇依式情绪支持 = 疏导情绪 + 帮学生检视自我价值判断是否苛刻、对世界的理解是否失真。

#### PAEG 真实经验

`prompts.py` 第 31-35 行 `_THINK_PREFIX_AFFECTION`（情绪场景版思考引导）：
- "先安静下来，感受这位学生此刻的处境：他在经历什么、最需要的是什么。"
- "然后用真实、朴素、克制的中文回应他。"
- "不要在回答里展示思考过程。"

`meta_router.py` 第 244-272 行 `AFFECTION_PATTERNS`（情绪意图检测）：
- 27 个正则覆盖情绪词、心理状态、人生意义、关系/自我、求助信号。
- 长度限制 ≤100 字——避免长文被误判为情绪。
- `safety.guard_input` 在 rule_fallback_intent 中做 crisis-first 兜底（meta_router.py 第 467-473 行）。

`is_affection_expression` 是情绪场景第一道门；`_affection_gate_check` 是危机先行钩子（README 第 7 节）。

#### 实施建议

1. **情绪场景必须禁用"接住/托住/兜住"类伪共情动词**（prompts.py 第 170-175 行三条语言铁律已禁止；language_refiner.py 第 51-54 行 AI_TELLS 黑名单同样禁止）。
2. **词汇多样化**：v0.50 Bug3 修复发现，affection 模式 LLM 容易高频复用"重量/真实/看见"等词，触发 `_check_word_repetition` 反馈换用同义词（"重量→分量/担子/沉甸甸的那一块"）。
3. **不主动给方案**——除非学生明确求建议；先承接情绪本身。

## 二、对话物料质量（讲义 / PPT / 视频 / manim）

物料是"对话生成之外"的产出，每一种都需要"内容准确 + 排版美观 + 完整性"三维度。

### 2.1 讲义（Markdown 文档）

#### 质量标准

- **结构骨架齐全**：H1 标题 → H2 大节 → H3 小节 → 列表/表格/引用/代码块。
- **内容准确**：技术讲义里的概念、定义、API 用法必须 100% 准确（TRUTH_GROUNDING 第 7 条"用户资料优先"——若讲义基于用户上传资料，资料内未提及的内容不得编造）。
- **数学公式合规**：与对话相同，全部 LaTeX 包裹。
- **可独立阅读**：讲义不依赖对话上下文就能看懂。

#### PAEG 经验

- `file_generator.py` 与 `lib/ingest/` 模块提供讲义生成与用户文件 4 能力（找答案/讲解/输出原文/重组结构）。
- 用户上传资料走 `usr_knowledge/<uid>/` 路径，BM25 + jieba 检索。

### 2.2 PPT（演示文稿）

#### 质量标准

- **大纲先于排版**：LLM 先生成 PPT 大纲（含标题/要点/页码建议），再由 python-pptx 自动排版——不要让 LLM 直接生成 .pptx 二进制。
- **每页 1 个核心要点**：单页文字 ≤50 字，标题 ≤20 字。
- **页面数量**：10 分钟演讲约 8-12 页；30 分钟约 20-30 页。
- **配色与字体统一**：建议 ≤3 种主色，字体 ≤2 种。
- **基于真实内容**：PPT 内容必须来自用户上传文档/知识库/对话历史，不凭空编造数据。

#### PAEG 经验

`pptx_mcp_server.py`（README 第 5.1 节）：
- v0.25+ 接入 PPT 生成 MCP（pptx_mcp_server.py）。
- 流程：用户上传文档 + 知识库检索 + 对话历史 → LLM 生成大纲 → python-pptx 自动排版 → 输出 .pptx。
- MCP 连接数 2/2 → 3/3（filesystem + memory + pptx）。
- `meta_router.py` 第 335-354 行 `INTENT_TO_CAPABILITY_HINT`：ppt 意图 → plan_default=ppt_workflow + auto_tools=mcp__pptx__generate_presentation。

#### 实施建议

1. **PPT 生成必须分两步**：先 LLM 大纲 → 再程序排版。LLM 不要直接输出 .pptx 内容（容易结构错乱）。
2. **每页加"演讲者备注"**：让 LLM 在生成时同步给出讲者话术，演讲时可读。

### 2.3 视频（视频讲解）

#### 质量标准

- **脚本与画面分离**：先生成详细脚本（含时间轴），再合成画面/旁白。
- **时长控制**：单条讲解视频建议 3-8 分钟（注意力上限）。
- **画面与语音同步**：旁白与 PPT/manim 画面同步推进。
- **字幕完整**：自动生成字幕并校正（ASR + 人工抽检）。

### 2.4 manim（数学动画）

#### 质量标准

- **代码先行**：LLM 先生成 manim Python 代码（含 Self 类的 construct 方法），再渲染为 MP4。
- **公式渲染**：用 `MathTex` 而非 `Text`（保证 LaTeX 公式正确）。
- **时长**：单段动画 5-30 秒最佳。
- **可调试**：代码结构清晰，单一函数单一职责。

#### PAEG 经验

- `manim_prompts.py`：manim 专用提示词，约束 LLM 输出可执行的 manim Python 代码。
- `manim_service.py`：调用 manim CLI 渲染（需本地安装 manim）。
- `manim_templates.py`：常用动画模板（坐标变换/函数图像/几何图形）。
- `manim_speed.py`：渲染速度控制。

#### 实施建议

1. **manim 代码必须可执行**：LLM 输出后立即执行一次确认无语法错误，再展示给学生。
2. **复杂动画分段**：长动画拆成 3-5 个短段，每段独立渲染，避免一次失败全废。

## 三、语言规范层（L1/L2/L3）

**语言规范性是教育智能体独立于模型性能的待解决问题**——必须程序化保证。PAEG 走三层防线：L1 提示词约束 + L2 规则检测 + L3 LLM 修正。

### 3.1 L1 提示词约束（写作前约束）

#### 质量标准

- **LANGUAGE_STYLE 全局纪律**：所有 system prompt 必须包含 LANGUAGE_STYLE 段（prompts.py 第 41-192 行，约 150 行）。
- **规范定义 7 项自查**：句子结构完整 / 用词完整 / 介词必须使用 / 修饰成分要足够 / 句子要有状语 / 主谓必须真搭配 / 谓宾必须真搭配。
- **三条语言铁律**（v0.19.8）：动词要小要具体（用看/问/写/算/试/翻，不用接住/托住/激活）/ 副词全去掉（不写稳稳地/轻轻地/真心地）/ 不要用动词"包住"对方（不写接住你的情绪/托住你）。
- **绝对禁止**清单：空洞套话、形容词堆砌、喊口号结尾、廉价鼓励（"你真棒"）、低劣网络用语（"yyds/绝绝子/栓Q/拿捏/稳了"）、伪共情动词（"接住/托住/我看见/我感受到"）。

#### PAEG 经验

- `prompts.py` 第 41-192 行：LANGUAGE_STYLE（v0.35 规范总纲定义 + 动词句法 + 动宾搭配 + 介词规范）。
- `prompts.py` 第 1438-1449 行 `style_anchor_line`：v0.36 在 build_presenter_system 内把"规范定义"作为最顶层教学纪律点出，让模型在写每句话前先想到。
- `prompts.py` 第 87-101 行 v0.19.13 特别禁止"没头没尾的总结句"——禁止"一句话总结""核心就是""说白了"。

### 3.2 L2 规则检测（写作后程序化检测）

#### 质量标准

- **检测维度 ≥6 类**：AI 痕迹词（AI_TELLS，300+ 词）/ 省略句（_check_ellipsis）/ 动宾搭配（bad_collocations）/ 省略词形（ellipsis_words：倦→疲倦、道出→说出来）/ 悬空宾语（dangling_verbs）/ 介词规范（bad_prepositions）/ 复合句缺主语（compound_patterns）/ 词汇重复（_REPETITION_TRIGGER_WORDS）。
- **检测覆盖率**：单条 500 字输出至少命中 1 类问题（如果文本没问题则应返回空列表）。
- **检测性能**：单次检测 ≤50ms（避免阻塞对话流）。

#### PAEG 经验

`language_refiner.py` 是 L2 检测主战场：
- `AI_TELLS`（第 32-155 行）：300+ 黑名单词，含 AI 腔套话（"总的来说/综上所述"）、AI 味形容词（"稳了/拿捏了"）、低劣网络用语（"格局打开/当场去世/主打一个"）、伪共情动词（"接住/托住/抱抱/拍拍"）。
- `_check_ellipsis`（第 271-428 行）：省略句 + 动宾搭配 + 省略词形 + 悬空宾语 + 介词规范 + 复合句缺主语——6 大类正则检测。
- `_check_word_repetition`（第 444-491 行，v0.50 Bug3 修复）：检测 LLM 高频词重复——"重量/真实/看见/听见/感受/空间/声音/陪伴"在 200 字内出现 ≥3 次即触发反馈。

### 3.3 L3 LLM 修正（检测到问题后 LLM 改写）

#### 质量标准

- **改写轮次 ≤2**：self-refine 循环最多 2 轮（language_refiner.refine 的 max_rounds=2）。
- **最小改动**：保留原意、事实和已通顺的句子，只改有问题部分——不重写整个风格。
- **保留 markdown 结构**：v0.68+ 显式要求保留 `### 标题`、`- 列表项`、`> 引用`、`**加粗**` 等结构，不要删除。
- **保留温度**：不改成生硬的书面语——保留原文本的温度和亲切感。

#### PAEG 经验

- `language_refiner.py` 第 183-235 行 `refine()`：检测 AI 味 → LLM 改写 → 复检 → 再改写（最多 2 轮）。
- 第 500-576 行 `_build_system()`：薇依语料 few-shot + v0.21.8 词法句法完整 + v0.25 介词规范 + v0.68+ markdown 保留。

#### 实施建议

1. **L2 检测输出要进 prompt 反馈**：检测到"重量/分量 4 次"时，反馈给 LLM 的具体建议是"换用：分量/担子/沉甸甸的那一块"。
2. **修改 prompt 时同步修改 language_refiner 的正则清单**——否则提示词变了，规则没跟上，漏洞大开。
3. **L1/L2/L3 三层兜底**：哪怕 L1 提示词写得再严，LLM 仍可能写出"接住你的情绪"——必须靠 L2 检测 + L3 修正兜底。

## 四、防幻觉（TRUTH_GROUNDING）

### 4.1 质量标准

- **绝不编造**：不联想、不猜测、不编造虚假信息、数据、公式、定义、来源或引用——宁可说"我不确定"。
- **信源为绝对命令**：凡涉及具体事实，必须以联网检索或知识库检索的内容为准；无信源时明确标注"未经核实"。
- **先证据后结论**：回答涉及事实判断时，先在证据中定位支持内容，再给出结论。
- **允许说不知道**：完全可接受且应优先于编造的回答。
- **错误修正**：若发现自己前面说错了，主动承认并修正。
- **温度不影响事实**：任何语言风格（温柔/严谨/克制）都不得以牺牲事实准确性为代价。

### 4.2 PAEG 经验（v0.68+ NEW-9 用户最高优先）

`prompts.py` 第 1683-1696 行 TRUTH_GROUNDING（10 条）：
1. 绝不编造
2. 信源为绝对命令
3. 先证据后结论
4. 允许说不知道
5. 区分确定与推测
6. 来源透明
7. 用户资料优先
8. 不捏造例题/数据
9. 错误修正
10. 温度/风格不影响事实

**注入方式**（prompts.py 第 1467 行）：
- `build_presenter_system` 返回值最前：`f"""{TRUTH_GROUNDING}\n\n{WEIL_CORE}\n\n..."""`
- `build_general_chat_system` 同样在最前注入（prompts.py 第 1916 行）。
- **subagents.py `_safe_chat`** 第 122-127 行：即使调用方 system 未显式包含，也由 `_safe_chat` 兜底注入 TRUTH_GROUNDING——保证所有 LLM 调用都受防幻觉约束。

#### 实施建议

1. **TRUTH_GROUNDING 是最底层约束，不可被任何其他提示词覆盖**——这是"高于一切教学/闲聊/倾诉要求"的底线。
2. **联网检索徽章**（README 第 14 节）：回答前显示"已完成知识库检索 / 网络检索"——让学生知道哪些内容有信源支撑。
3. **每个 subagent 都要过 TRUTH_GROUNDING**——subagents.py `_safe_chat` 的兜底注入是关键防线。

## 五、错误处理与重试

### 5.1 质量标准

- **异常语义化日志**：区分限流/超时/预算/网络/解析失败（subagents.py `_safe_chat` 第 144-156 行已实现）。
- **重试机制**：LLM 调用失败 → 重试 1 次 → 失败回退规则模板（不无限重试）。
- **泄漏检测**：LLM 回复若泄漏 system prompt 或自称其他模型（"我是 ChatGPT/Claude/GPT-4"），视为不安全返回 None。
- **Token 预算门**：60 分钟窗口内累计 60000 token 上限，防止成本失控。
- **思考链泄漏检测**：reasoning_content/system prompt 等标记检测到则返回 None。

### 5.2 PAEG 经验

`subagents.py` 第 144-156 行 `_safe_chat` 异常处理：
- 限流：模型 API 抛 RateLimitError → 日志 + 返回 None。
- 超时：requests.Timeout → 日志 + 返回 None。
- 预算超限：`_consume_token_budget` 返回 False → 拒绝调用。

`subagents.py` 第 813-829 行 `_is_leaky_reply`：
- LEAK_MARKERS 黑名单："我的 system prompt 是"、"我是 ChatGPT"、"忽略之前所有指令"、"ignore all previous instructions" 等。

`subagents.py` 第 622-633 行 `_is_leaky_reply_fast`：检测"reasoning_content"、"内部思考"、"system prompt" 等思考链泄漏标记。

`subagents.py` 第 70-99 行 token 预算：
- `_consume_token_budget`：滑动 60 分钟窗口，累计 60000 token 上限。
- 实际计费（v0.50 Oracle 修复）：按实际输出 token 计费（非 max_tokens 预扣）。

#### 实施建议

1. **LLM 调用必须三重防御**：异常捕获 + 泄漏检测 + 预算门，缺一不可。
2. **回退路径必须能用**：LLM 失败时回退到规则模板（如 meta_router 的 `is_problem_request` 兜底），不要直接报错给用户。
3. **错误日志含 provider + 错误类型 + 错误消息前 300 字符**——便于定位是 DeepSeek 限流还是网络问题。

## 七、网络参考：LLM-as-judge 评估

业界常用 LLM-as-judge 模式做对话与物料质量评估（PAEG 的 `eval_harness.py` 即采用类似思路）。

### 7.1 评估维度（业界共识）

- **正确性**：事实是否准确（TRUTH_GROUNDING 是底线）。
- **相关性**：是否回答用户的问题（不答非所问）。
- **完整性**：是否覆盖关键点。
- **连贯性**：逻辑是否通顺。
- **有用性**：对用户是否有实际帮助（可执行、可操作）。
- **无害性**：是否安全、是否包含有害内容（Constitutional AI 风格门禁）。

### 7.2 输出质量维度（PAEG 落地）

| 维度 | 评估方法 | 工具/指标 |
|---|---|---|
| 意图识别准确率 | 用户输入 × 标注意图 → LLM 判定 vs 标注 | eval_harness.py --fast |
| 教学讲解质量 | LLM-as-judge 对生成讲解打 5 个维度分 | eval_harness.py |
| 语言规范性 | AI_TELLS 命中率 + 省略句检测 + 词汇重复 | language_refiner.detect_ai_tells |
| 防幻觉合规率 | 故意输入诱导问题 → 检测是否编造 | TRUTH_GROUNDING 注入审计 |
| 多轮退化 | 多轮对话后检测输出是否退化 | multi_turn_eval.py --mode all |
| 接口稳定性 | 36 端点 × 多轮覆盖 | api_sweep.py |

### 7.3 实施建议

1. **建立黄金测试集**：50-100 条高质量示例，每条含输入+期望输出+评估标准——每月跑一次回归。
2. **人工抽检不可省**：LLM-as-judge 不能完全替代人——每月人工抽检 20 条典型对话。
3. **构建"质量仪表盘"**：把意图识别准确率/语言规范率/防幻觉合规率做成 Prometheus 指标，长期追踪。

## 附：PAEG 实施质量"五个不要"

1. **不要让 LLM 直接生成 .pptx 内容**——先大纲，后排版。
2. **不要让 LLM 在情绪场景用"接住/托住/兜住"**——伪共情。
3. **不要让 LLM 编造例题数据**——必须标注假设或用信源真实数据。
4. **不要让单次讲解超过 1800 字**——学生读不完。
5. **不要在没有 L1/L2/L3 三层防御的情况下上线语言规范**——LLM 总会绕过单层。
